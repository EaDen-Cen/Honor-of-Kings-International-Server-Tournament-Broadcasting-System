# HOK Broadcast v1.0.0 发布说明

**状态：Release Candidate（2026-10-10）。正式发布日期与 tag 以 GitHub Release 为准。**

这是 HOK Broadcast 首个公开版本的发布候选，面向 Honor of Kings 国际服社区赛事。它将导播、解说延迟数据、OBS 图形和本地屏幕识别集中到同一比赛状态中。本版以源码分发，需要 Node.js 24；尚无独立安装包。

## RC 屏幕识别修正（2026-10-11）

- Pick 依据当前选手头像底部勾号确认；双选逐位检查，最后一手与跨阶段统一处理。
- Ban 改为检查当前头像的锁形标记，匹配英雄时排除锁标遮挡；不再凭局部画面变化推断锁定。
- 低分识别保留未知，空 Ban 仅人工确认，避免真实英雄被误跳过。
- 支持模板多裁切、完整英雄池人工纠正，以及本地保存识别裁图供复现。
- 已用用户提供的静态游戏裁图检查蓝/红 Pick 勾号与 Ban 锁。尚未完成真实游戏连续流程验收；海月、弗洛伦、影、敖隐、拉普拉普五个反馈案例缺少对应原始识别裁图，不能宣称全部解决。

## 本版提供什么

- **完整导播流程**：BO1/BO3/BO5、Match/Normal BP、普通/选手/全局 BP、蓝红先手与换边、有效局历史、人工比分、Undo 和重置。
- **解说与直播图层**：Caster 延迟 BP、比分与比赛进度；队伍/选手/赛事资料和展示配置实时更新。Draft Overlay 提供底部横排和左右竖排，OBS 使用 1920×1080 Browser Source。数据延迟不包含视频或音频延迟。
- **本地识别与人工回退**：浏览器窗口采集、18 个英雄槽位校准、空 Ban 与双 Pick、P1–P5 Player ID 排序、最终阵容/角色交换。低置信度可人工确认或修正；自动输入须主动启用。
- **赛前与恢复工具**：队伍库、首发/替补、选手照片、自动备份、停机恢复、比赛导入导出与访问角色隔离。
- **Simulator**：按 **选手 ID 排序 → BP 模拟 → 角色交换** 测试。默认隔离比赛；Control → Simulator 只读。显式开启 Control 联动并同步测试基线会修改比赛，请使用测试比赛。
- **英雄数据库**：当前基线为 119 个英雄/形态条目，完整名单见 [hero-roster](../research/hero-roster.md)。ID 按国际服上架顺序编号；旧存档自动迁移，头像文件名保持独立。Hero Sync 后续更新通过候选 PR 审核。
- **赛后 MVP 基础链路**：手动指定结算页、字段与区域，本地 OCR 生成十人草稿，人工复核后选择 MVP 并展示；程序不评判 MVP。

## Experimental 与不包含的能力

**Game HUD 为 Experimental**：可人工维护人头、推塔和资源，系列赛信息读取比赛状态。自动读取游戏 HUD 尚未实现。正式比赛保留官方观战 UI 或裁判记录作为权威来源。

赛后自动判页、稳定画面检测、跨页一致性校验、全队数据页、远程 Vision AI、OBS 自动切场景、自动视频同步与桌面安装包均不在本版已实现范围。固定域名 Docker/Caddy 配置可供试用，未验证实际托管环境。

### 最终阵容与换英雄

- BP 历史与最终英雄归属分离。
- BP 完成后扫描 10 个 Pick 槽。
- 每队只在本队已 Pick 的 5 个英雄中求不重复最终分配。
- 稳定检测到英雄互换后自动同步。
- 支持“立即识别并应用换英雄”和人工下拉修正。
- Simulator 中“换英雄同步”与 BP 识别完全独立，可单独建立测试基线。

### BP Simulator

- 独立控制页与干净采集页。
- 三种互不混淆的测试：**BP 识别 / 换英雄同步 / Player ID 排序**。
- 新增“从 Control 同步模拟器数据”：可把当前 BP、最终英雄归属或 P1–P5 信息单向读取进对应 Simulator 测试，不会修改正式比赛状态。
- 换英雄测试可以直接复用 Control 已完成 Draft 的最终 assignments 作为基线；计时期间锁定再次交换，完成后才允许下一轮。
- Simulator v2 localStorage 中的旧 hero ID 会自动迁移到新的 release-order ID，避免英雄重新编号后测试画面错配。
- Match / Normal BP、蓝/红先手、圆形 Ban、空 Ban、双 Pick。
- 自动脚本支持最短/最长等待、随机切换预选英雄、最终稳定窗口与可调锁定 cue。
- Pick 头像 48–104px、Ban 位 24–64px 可实时调节并持久化。
- Player ID 模式会随机双方队内顺序并自动计时。
- Windows 一键后台启动与停止脚本。

### 英雄数据与图片

- Hero Data Synchronizer 持续维护当前英雄池。
- 已加入 Wang Wei / 王维（release-order ID 119，Camp ID 138）；新英雄同步在辅助详情页 5xx 时可使用官方 HOK 身份与 Key Art 兜底。
- 中英文、alias 与搜索。
- 英雄图片/数据运行时 override。
- 可搜索头像网格编辑器。
- Panel / Side 图片裁切与预览；现场保存写入 `data/match.json`，可用 `hero:crop-sync` / `sync-hero-crops.bat` 提升为 Git 跟踪的公共裁切默认值。
- Flowborn 形态合并/独立规则。

### 备份与恢复

- 数据变化后自动备份，保留最近 20 份。
- SHA-256 / 路径 / 大小校验。
- 停止后端后的完整恢复与比赛导入。
- 比赛导出排除访问凭据；完整备份包含本机访问配置。
- 单后端进程锁与有界操作日志。
- Control 可查看备份状态、立即备份和导出比赛。

### 赛后数据与 MVP

- 有效局固定十人身份、英雄与照片。
- 可按总览/生存/输出/团队等页面手动选择字段并批量 OCR。
- 保存字段来源、置信度与原始裁剪证据。
- 人工修正确认不会被低置信度 OCR 覆盖。
- MVP 由语音频道投票或赛事方人工决定；系统**不自动评判 MVP**。
- `/overlay/mvp` 使用统一蓝/红模板展示选中的 MVP。
- 自动判页、稳定画面检测与真实游戏全部结算页覆盖仍属于后续验收。

### Experimental：局内 Game HUD

`/overlay/game-hud` 已实现：

- 双方队伍身份与 Logo；
- 系列赛大比分；
- 当前 Game / BO / Stage；
- 当前小局人头、推塔；
- 最多六类可配置中立资源；
- 简约 / 完整密度；
- Undo、刷新/重连恢复、下一局计数重置。

**v1.0.0 中 HUD 仍标记为 Experimental。** 当前局内统计主要由 Control 人工维护，自动读取真实游戏 HUD 尚未实现；真实 OBS 长时间运行、不同游戏 UI 版本、误操作恢复和最终视觉遮挡仍需赛事现场验证。

## 性能与稳定性

- 各角色快照缓存与延迟事件二分查询。
- 英雄识别减少中间图片编码、重复裁剪与重复画面计算。
- 完全相同画面证据缓存。
- 重型编辑器与 Simulator 按需加载。
- Overlay / Simulator 使用固定设计画布并随窗口等比缩放。
- Player ID OCR worker 在后端启动时预加载并常驻。
- Player ID 首轮 fast path、按队追加候选、100ms 后台复核调度，同一时间最多一个 OCR 请求。
- CI 已覆盖英雄数据校验、生产 Build、服务器/单元测试与 ESLint；真实 HOK、OBS 和 Windows 赛事机仍需现场 smoke test。

## 推荐发布前彩排

1. 使用 BP Simulator 完整跑一轮 Match BP。
2. 将随机选角压到约 1.5–2 秒，确认 Auto BP 仍稳定。
3. 运行 Player ID 队内乱序测试，确认双方顺序自动同步；再测一次人工采用和恢复自动。
4. 校准真实游戏的 18 个英雄框和 10 个 ID 区域并分别保存预设。
5. 测试双 Pick、空 Ban、Pick→Ban、最后一手和至少一次换英雄。
6. 检查 Draft Overlay、Caster 延迟与断线重连。
7. 停止/重启后端，检查比赛状态与备份恢复。
8. 如果启用 Game HUD，仅作为 Experimental 功能单独彩排，并保留人工/官方比分兜底。
9. 如果启用 MVP 页面，至少跑一次结算页 OCR + 人工修正 + 蓝/红两种 MVP 卡片。
10. 真实 OBS 录制至少跑一段持续测试，重点检查此前出现过的音画不同步/停止录制问题。

## 已知边界

- 图像识别依赖实际游戏 UI、头像裁切、亮度、缩放和版本；游戏更新可能需要重新校准。
- Player ID 最佳约 1.8 秒和 BP 1.5–2 秒压力成绩来自当前 Simulator/测试环境，不是所有硬件的保证。
- ID 区域与 18 框预设保存在 Director 浏览器 localStorage，不会自动跨电脑同步。
- 日文等额外 Player ID 语言需要对应 Tesseract traineddata。
- Game HUD 仍是测试功能，自动 HUD 读取未实现。
- 赛后 MVP 自动判页/全结算页覆盖未完成。
- Caster 延迟是数据延迟，不是视频平台延迟。
- Cloudflare Quick Tunnel 地址每次启动可能变化。
- 固定域名 Docker/Caddy 配置已预留，但尚未作为 v1.0.0 的已验收托管环境。
- OBS、直播平台、远程解说和 Discord 的完整端到端音画同步仍需要赛事现场彩排。

- 119 位英雄按国际服 Launch Time 从旧到新连续编号为 `1..119`；“上线时间（新→旧）”直接使用 ID 降序，旧版 match.json 会自动迁移。图标文件名保持原资产编号，不做破坏性批量重命名。

## 从开发版本升级

1. 停止后端并备份整个 `vite-project/data/`；自定义 `UPLOAD_DIR` 另行备份。保留浏览器校准预设所在 profile，避免清理站点数据。
2. 下载正式 Release 对应的完整源码或切换到已发布 tag；不要覆盖或删除运行数据，不复用旧 node_modules。
3. 在 `vite-project/` 运行 `npm ci`、`npm run build`，然后 `npm run server`。
4. 刷新 Control、Caster 和 OBS Browser Source；核对存档迁移后的英雄、历史、照片、比分与最终归属。
5. 重新核对 18 个英雄框、10 个 ID 区域和命名预设。它们保存在浏览器 localStorage，不随服务器备份自动跨电脑迁移。

完整备份含访问凭据；比赛导出不含访问凭据。回退旧程序前恢复升级前备份，不能假设旧版本能读取新版 ID/schema。恢复方法见 [恢复指南](../guides/player-alignment-recovery-hud.md)。

## 使用边界与现场彩排

- 识别依赖游戏 UI、头像、缩放与亮度，游戏更新后可能需要重新校准；日文等额外 ID 语言需安装对应本地 traineddata。
- 既有 Simulator BP 1.5–2 秒窗口和 Player ID 最佳约 1.8 秒是测试观察值，不保证所有赛事设备性能。
- 当前 UI 图标为本地资源；Full Art 和部分识别模板使用官方 CDN，网络不可达时应检查降级画面。
- Quick Tunnel 地址可能随启动变化；远程使用角色分享链接，解说不可获得 Control/Overlay 凭据或实时游戏画面。
- 发布前在赛事机完整跑两种 BP、ID 排序、角色交换、人工回退、Caster 数据延迟、OBS 刷新/重连与持续录制。另测远程解说、Discord/直播平台的实际音画同步。
- 启用 HUD 时检查遮挡、统计和回退；启用 MVP 时实际完成结算页校准、OCR、人工修正和蓝/红卡片展示。
