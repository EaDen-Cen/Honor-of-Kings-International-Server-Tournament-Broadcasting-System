# 真实设备验收清单

本清单尚未执行；自动测试、Windows 启动器脚本及模拟 OBS/Discord 不等于下列实机通过。先在测试赛事和测试频道操作，记录代码 SHA、Windows/Node/浏览器/OBS 版本、分辨率、采集方式、时间及证据文件。

| 项目 | 操作与通过标准 | 必须留存的证据 |
| --- | --- | --- |
| 升级与恢复 | 停服备份比赛、资料库、上传素材和配置；使用原 Windows 用户启动；在副本上完成恢复 | 备份校验、重启后各局数据、恢复日志；不上传密钥 |
| 单实例启动器 | 双击启动、重复启动、关闭窗口、异常退出后重开；不得终止无关 Node/OBS 进程 | 进程/端口、启动器日志 |
| 本机与平板 | 本机 Control 正常；平板获得 Control 授权后可操作；远端 OBS 接口应保留本机限制 | 两端截图、断线恢复记录 |
| 开播清单 | 检查真实 Node/模板/观看连接、OBS、录制盘；未通过项不得靠勾选变绿；绕过留下实际失败项目 | 清单与绕过历史（含时间），浏览器存储失败提示 |
| 队伍与赛制 | 双方 Logo/五名首发/P1–P5，分别 BO1/3/5/7；管理器显示全部潜在局，核对单局英雄池、Ban 数、历史限制/贡献；改名单后重新核对 | 七局计划、保存 ACK 和刷新前后截图 |
| 混合逐局规则 | 穿插 Match、正常零 Ban 与 Blind；盲选无需 BP 识别或十名英雄即可开局，仍可 GHUD/赛后录入；下一局自动切换预设；修改未来局不改变已完成规则 | 规则快照、切局录像、盲选空英雄报告和历史资格对照 |
| OBS 场景与源 | Waiting/BP/Game/Postgame/MVP/Safe 指向实际场景；核查 1920×1080 Browser Source 的内容、尺寸、层级和变换 | OBS 场景与预览；不能只拍“已连接” |
| 录制与磁盘 | 在实际录制目录启动/停止；检查容量读数与系统一致，目录不可用/空间不足显示警告 | OBS 输出目录、容量、可播放文件；不要填满生产磁盘测试 |
| 音频 | 检查实际麦克风、游戏音、BGM 的电平和录制声音；手动淡入淡出与跨场景操作不突变 | 录制片段及电平截图 |
| BP 识别 | 真实十人房间完整 BP；锁定/未锁定、候选切换、换位、英雄误识别可人工纠正且 Undo 有效 | 标注头像/锁定裁图、操作录像、服务端确认 |
| 元流之子 | 五职业形态与孙尚香负样本，多个缩放/皮肤/亮度/锁定阶段；记录第一候选、置信度、间距和人工结论 | 私有标注 JSON 供 HOK_HERO_RECOGNITION_SAMPLE 使用；不得用模板图替代 |
| GHUD 稳定采集 | 同一视频源预热，核对七区；连续真实动态画面两帧正确后开启自动；默认一秒尝试不积压 | 采集→OCR→ACK 时间及可信时间，不只看 OCR 耗时 |
| 遮挡挑战 | 用真实系统回弹/浮窗/通知/动画遮挡时间和部分数字；错误不能更新权威数据；保留旧值并提示 | 遮挡前/中/后的完整帧、ROI 和事件时间线 |
| 遮挡恢复 | 移走遮挡，至少两帧重新验证；持续暂停截图不得推进；切换尺寸/源后必须重校准 | 恢复用时、误更新次数、人工冻结字段不被覆盖 |
| 人工接管 | 分别改比分、局内数字和锁定英雄；自动循环不得静默覆盖；逐项取消冻结后才恢复 | 修改前/后与后续自动样本 |
| BO3/BO5/BO7 | 每局录不同评分/数值，换边、重复提交、Undo、刷新、服务重启、回看历史；BO7 分别验证 4:0 与 4:3，第 1–7 局数据独立且不能创建第八局 | 七个稳定报告 ID、各局规则/结果、导出数据及恢复后对比 |
| Caster/Overlay | 实际远端打开并观察延迟；BO7 比分 0–4 与七局上限正确，盲选不残留上局英雄/Ban；断网恢复后规则一致、不重放旧 action | 双端时间线/录屏、方格比分、真实公网链路 |
| Webhook-only | 测试频道只配置 Webhook；预览不发，点击后有消息 ID；MVP 与已确认 Overlay 相同 | 脱敏本地日志、频道消息与时间 |
| Discord 故障 | 断网/权限撤销后提示失败或未知；未知状态人工核对；不自动重发 | 失败/恢复日志、重复消息数；不公开 Webhook URL |
| AI 费用 | 默认零预算、离线本地可用；小额测试验证额度扣除、备用计数、重启后保留，达到限额停止 | 脱敏调用记录与供应商账单对照；估算误差 |
| 持续彩排 | 一人独立完成完整七局的 BO7，包含混合规则、录制、音频、OBS、Discord、历史回看与导出 | 全场录制、异常清单、资源使用与最终签字 |

识别验收至少分别报告有效样本数、正确数、误识别数、拒绝数、误更新数、遮挡恢复耗时和端到端延迟分位数。拒绝样本不可从分母中悄悄删除；模板衍生图片与真实游戏图片分开统计。出现高置信度误更新时保留 GHUD Experimental，并用人工字段/官方画面继续赛事。

通过标准由赛事负责人对真实流程签字确认；当前没有真实设备/凭证/样本，因此不能给出实机通过或正式上线承诺。
