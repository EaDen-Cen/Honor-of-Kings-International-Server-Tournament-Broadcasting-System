# Phase 2：赛后状态职责提取

在 Phase 1 基础上，将赛后报告创建、字段校验与合并、字母评级、队伍汇总、经济曲线和 MVP 选择集中到 `server/postGameActions.ts`。`Store.apply` 仍负责 action ID 去重、revision、复制事务、Undo、事件、延迟快照和原子保存；新模块不读写磁盘，不持有第二份 MatchState。

接口只有 `preparePostGameReport(state, game)` 和 `applyPostGameAction(stagedState, action)`。后者对不属于赛后的 action 返回 false；对非法赛后输入抛错。调用者只传已复制的事务状态，失败不能修改权威快照。报告复用逻辑与人工优先级直接移动，保留原来的错误和数据结构。

Store 减少 98 行集中实现。没有创建新的路由框架、事件总线或存储层，没有改变协议或存档版本。现有 `postGameValidation.ts` 继续作为输入校验实现；Capture、OBS 和识别已经存在独立模块，后续只在明确行为边界上迁移。

验证：`npm run build`、`npm run lint` 通过；原有完整单元测试 338 通过、0 失败、2 跳过，含 BO1/3/5、重启、Undo、历史报告与非法字段原子回滚。浏览器验证仍依赖 Phase 1 全量结果及本分支后续 CI；真实设备未验收。

回滚：revert 本阶段提交即可，数据结构不变。主风险是分派与 Undo 快照顺序；完整 Store 测试已覆盖，不能改为先修改权威 state 再校验。
