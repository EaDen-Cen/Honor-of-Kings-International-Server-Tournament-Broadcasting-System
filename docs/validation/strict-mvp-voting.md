# 无 Bot 严格 180 秒 MVP 投票验证

日期：2026-11-05。分支：`codex/webhook-mvp-voting`，基于已合并 #109 的 main `b143729`。本功能尚未合并或发布。

## 方案结论

Discord 原生 Poll 的时长为整数小时，Webhook 没有提前关闭接口。软截止文字不能代表三分钟收票终止。本轮采用 Webhook 发布独立 HTTPS 页面链接，由本服务的服务器时间在每次提交时判断截止，不读取 Discord 原生 Poll 票数。官方依据及完整配置步骤见 [操作指南](../guides/discord-mvp-voting.md)。

新增 12 项单元/服务测试覆盖：

- BP 提交不发票；Store 的明确比赛结束确认才触发，且不改比分、阶段和队伍预设。
- 第 179999 毫秒收票，第 180000 毫秒拒票，不依赖 tick；匿名票据重放幂等，换候选重复投票拒绝。
- BO1/BO3/BO5、下一局不同投票、历史局 MVP 确认不切换当前报告；Overlay 状态、Store 文件恢复和身份校验。
- 胜方五人、名单/分路冻结与变化提示、提前关闭、取消、Undo 后终态不重开。
- 文件重读模拟服务器恢复、已发消息对账、不确定投递不自动重发、429 冷却后重试。
- 前一公告在途时观察下一局结束确认，防止快速切局漏掉创建。
- 原子写入失败后拒绝新票，保留已接受票；手动发布、配置校验和既有候选不随设置变化。

浏览器测试使用实际后台和实际 180 秒墙钟等待，没有缩短产品期限、修改服务器时钟或仅改公告文字。覆盖配置界面、自动发起、公开页面、浏览器重复提交、设备墙钟错误、截止后 HTTP 拒票、结束通知、人工 MVP、MVP Overlay，以及跨局/历史修改/取消。Discord HTTPS 发送在测试进程中使用替身，不发送到真实频道。

一次中间全量测试失败于既有 JPEG 上传测试：操作系统分配的随机端口被 Node fetch 的 forbidden-port 规则拒绝（`bad port`）。修正为 Node HTTP 客户端，保留状态码、上传文件、JPEG 格式和尺寸的所有断言。最终全量重跑 364 通过、2 跳过；没有删除测试或放宽断言。

## 未实测及运行边界

- 两项跳过仍是既有私有真实英雄/锁定裁图及十人校准样本测试，不属于投票故障。
- 本轮跑了相关的三项 Playwright 回归，未重新执行整个 E2E 集及 Windows 启动器/隧道脚本；此前 #109 全量结果是独立记录，不能当成本轮新功能验收。
- 没有真实 Discord Webhook 联调、真实公网 HTTPS/反向代理/隧道验证、实体平板或现场赛事验收。重启测试是持久化文件重读和中断状态恢复，不是整机断电测试。
- 没有 Discord OAuth；匿名浏览器标识可被清除或跨设备绕过，不能保证一人一票或防专业刷票。请求按连接地址限流，共享代理会共享额度；未验证大型观众并发容量。
- 180 秒从服务器创建投票起算，公告延迟或重试不延长窗口；结束通知可因网络延迟晚于硬截止。服务器停机期间不收票，恢复后不补时。
- Webhook 超时可能无法判断是否实际送达。已成功的消息不会自动重发，不确定状态必须先核对频道；手动允许重试可能产生同一链接的重复公告，但不会生成第二次有效投票。
- 投票文件及 Webhook 日志需另外保管；比赛旧导出格式不包含它们。回滚前关闭活动投票并保留文件，旧版本不会继续服务新的投票页面。
