# 2026-10-18 · 两场真实赛事转播复盘（现场观察）

> 来源：导播现场反馈。以下仅记录实际观察，不等于自动化验收结果。完成代码调整后仍需 OBS + 真机双场复测。主线是**降低单人导播负荷**，不以继续添加复杂设置为目标。

## 已通过/暂不回退

- 先前需要修复的核心 BP 识别，在这两场赛事中除列出的元流之子个例外基本稳定。
- 录制链路之前的音画同步故障已解决；第二场录制中断的直接原因是 **E 盘空间耗尽**，不是已确认的新音画同步故障。
- MVP 播出页面能正常工作，仅剩细节问题。
- 不因本复盘回退已经验证的 BP 流程、MVP 模板、录制设置；新增功能必须避免影响现有并发性能。

- **最终阵容归属未真正应用（P0）**：系统识别到了英雄更改，但现场权威 `assignments` 未按预期更新。代码包含唯一匹配、最低/平均相似度、两帧稳定和比赛状态限制，且发送动作后先显示“已发送自动同步”；目前没有证据证明哪一步失败，不应擅自归结为识别算法错误。
- **开发验收**：区分候选识别、发送、服务端接收与成功持久化；将拒绝/超时原因反馈导播；支持帮抢/互换、P1–P5 排序、蓝红换边、手动接管、后端拒绝及切局竞态；仅已确认的最终英雄绑定可用于赛后对位与未来 OBS 自动转场。
- [修复及 OBS 前置依赖详细方案](../design/obs-websocket-integration-roadmap.md#6-最终阵容归属可靠性m12m12a-前置-p0)。

### 2026-10-19 · 实际源码修改（待验证）

- `LineupAssignments.tsx` 原先强制两队均可靠才允许应用，导致另一队 OCR 不确定时阻断已可信的单队英雄互换。新版允许可信一方独立更新，另一方保持权威已存阵容。
- `useMatch.ts` 对动作是否真正排队发送返回布尔值；最终阵容仅在服务器 ACK 且实际 MatchState 相符时显示成功，拒绝/未入队明确显示。
- 手动选择支持仅应用已解析的一队；降低误拦截而**不降低自动可信阈值**。
- 这些是待 CI 及真机验证的源码修改，不等于全部帮抢与历史角色绑定问题已解决。

| 2 | 元流之子形态难以识别，游走（元辅）误判为孙尚香 | P0 | 独立收集元辅和混淆英雄的裁图、校验图库与置信度；在可靠前保留人工候选与禁止未知高分自动提交的保护 |
| 3 | 第一局未执行选手 ID 排序，赛后错误跨位置比较 | P0 | 导播工作台每局 P1–P5 显式核对提醒（本机/当前会话），对位缺失或重复角色拒绝展示；**不能凭提醒证明后台已核验身份** |

另外：现场反馈指出**识别运行时无法点击人工候选按钮**。本次 PR 解除了 busy 禁用，人工点击会中断当前 OCR 请求，避免旧请求迟到覆盖人工选择；仍须浏览器/实机回归。

### 本次 PR 中已提交源码的范围（不代表已经发布）

1. BP 手动候选优先于后台扫描，可随时中断正在运行的 OCR，并保留同一阶段、同一来源的候选。
2. 五个 OBS 对位页面独立、固定角色，没有页面内角色切换，构图改为左右选手与中央雷达/数字。
3. Control 增加每局 P1–P5 人工核对提醒（sessionStorage 当前标签页），供导播赛前防漏；旧历史赛后数据无法被此机制自动重新绑定。
4. 补充 E2E 回归：五条固定 URL 在 1920×1080 下可见、候选按钮在后台扫描中可点击。

### 五个 OBS 浏览器源

```text
/overlay/postgame-clash   对抗路
/overlay/postgame-jungle  打野
/overlay/postgame-mid     中路
/overlay/postgame-farm    发育路
/overlay/postgame-roam    游走
```

可以为 OBS 每个页面建立独立 Browser Source，切换场景时只切源，不在网页里切角色。仍兼容旧版 `/overlay/postgame-compare?role=clash|jungle|mid|farm|roam` 链接以避免现有 OBS 失效。

### 下一次比赛的现场流程（临时，不等同自动化已实现）

- **赛前**：确认游戏来源、双方首发/角色、P1–P5 真实顺序和换边；确认 OBS 录制路径、可用容量、输出码率、录制测试与备用方案；把每个独立对位网页和 MVP 预先加入 OBS 场景。
- **BP**：让自动识别承担正常 Ban/Pick；元流之子形态与帮抢由人工审核；当候选错误或扫描未结束，立即点击“手动确认候选”，切勿勉强等待识别。
- **进入游戏**：再次核对 P1–P5 与最终使用英雄，特别是帮抢/交换；确保对位信息使用角色绑定，不把 P1 默认当作对抗路。
- **局内**：GHUD 当前仅 Experimental，不把未经核实的经济/中立统计作为正式信息。音乐可留空，优先确保画面和录制可靠。
- **结算**：优先采集有证据的 10 人数据；先验身份、再验数字、最后出 MVP/对位，经济/雷达缺失显示空状态，避免错播。
- **两局之间**：检查 OBS 正在录制与目标盘剩余容量，按实际码率估算足够空间，必要时切换备用目录。

### 待开发验收要求

- **人力负担**：正式彩排测量每场导播主动操作次数、紧急补救次数、从 BP 到 Game 的切换耗时及赛后出图耗时。
- **错认与帮抢**：准备元辅、元坦、元射、元法、元刺及孙尚香真机截图，测量混淆矩阵；覆盖选手帮抢后交换、半途取消、最终英雄归属一致性。
- **图形**：OBS 1920×1080 全部五路分辨率与照片缺失测试；GHUD 与正式赛事风格对比在不复制专有资产的前提下重做。
- **赛后**：至少两场真实结算全页，记录数字正确率、身份匹配准确率和出图时间；低置信度不得自动填充；经济时间序列必须来自可核实截图刻度或连续观测。
- **录制**：测试容量警告阈值、可配置路径和中途磁盘耗尽时的报警/降级；不能依赖网页直接读取任意本地盘空间。
