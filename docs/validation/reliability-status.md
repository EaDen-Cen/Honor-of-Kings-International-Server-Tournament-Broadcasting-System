## 任务书问题逐项回答

1. **是否更容易维护、快速定位？** 有明确模块/调用地图，赛后纯操作从 Store 分离，新增 Webhook 与预算各自负责副作用；仍需逐步拆分 server 路由，不能说架构问题全部消失。
2. **是否两份比赛状态？** 比赛、比分和报告仍只有 Store 权威状态。浏览器草稿、OBS 状态、Webhook 投递日志和 AI 账本均不作为第二份比赛状态；模拟器显式隔离。
3. **BO5 能否连续录五局不同赛后数据？** 新 Store 与浏览器回归覆盖五局独立值、历史再打开和刷新；真实全场仍需现场彩排。
4. **遮挡是否可能错误更新？** 简单空白覆盖已被逐字段否决；可信校验和人工冻结仍有效。复杂带文字浮窗仍可能形成看似合理数据，不能作绝对安全承诺。
5. **元流之子是否还可能高置信度误判？** 没有真实复现样本，无法排除；只证明当前模板/合成集通过，人工纠错入口可用。
6. **BP 锁定后能否人工修正？** 可以，当前/历史局按槽位纠正并保留 Undo 和人工统计；服务器继续禁止重复或不可用英雄。
7. **无 Bot 权限能否通知与 MVP 发布？** 可以使用已授权的 Webhook；测试验证了独立流程，真实频道待验收。投票结果需人工确认。
8. **费用是否受控？** 实际发请求前计入持久化次数和估算预算，超额或账本故障停止；供应商实际账单需对账并另设硬限额。
9. **GitHub Actions 全部通过了吗？** 本次最终集成的验证提交、完整本机结果与 GitHub 工作流状态统一记录于 [最终集成记录](final-integration-2026-11-05.md)。
10. **能否证明没有破坏核心功能？** 以固定提交的完整回归、定向复现和 Windows 脚本为证据；无法用测试数学证明无所有缺陷，也不能替代真机。
11. **下一场能否按明确流程准备？** 见 [操作指南](../guides/operator-guide.md)，包括真实检查、人工确认、BP、游戏、赛后、通知、下一局和恢复。
