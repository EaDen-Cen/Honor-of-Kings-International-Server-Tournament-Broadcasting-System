# Phase 1：可靠性修复

阶段一修复随 #109 合入。跨局报告之后扩展至 BO7 和盲选，测试资料保护范围见[三局回归](storage-ocr-reliability.md)。

基于 Phase 0（PR #100），合入 PR #99 的原提交历史并继续修复，不重复创建英雄纠错、录制容量或报告服务。main 尚未改变。

## 修改与根因

- BO3/BO5：`next_game` 原来保留 activePostGameReportId，导致进入下一局仍编辑上一局。现在撤销前保留完整快照、进入下一局取消报告选择，历史数据保留；commit 使用 #99 的逻辑创建/选择本局空报告。切换报告清除截图、候选与未完成请求，防止前局画面被继续使用。历史报告仍可显式打开。
- GHUD：人工字段修改后旧候选仍可提交。人工来源改变时清除候选并要求新采样；普通 OCR ACK 不清除，避免自动采样循环停摆。
- 浏览器回归：设置入口迁移至既有 Settings dock；Simulator 的 status 定位限定到真实同步提示；静态画面的提示断言与当前拒绝行为保持一致。自动采样测试用第三次响应屏障固定观察点，保留准确的 20 秒及后续推进断言，不依赖 5 秒恰好采样两次。
- Linux E2E：每个隔离后端生成独立临时 HOK_CONFIG_KEY，使加密配置写入测试有合法密钥；Windows 继续使用真实 DPAPI。不将测试密钥写入仓库或日志。
- 布局：工作区根据实际顶部位置占用剩余窗口高度，手动 picker 在 dock 内使用自身容器高度，开播清单折叠后仍显示未完成/绕过状态。保留 1920×1080 和 1440×900 同屏可见、键盘 BP 及无页面滚动断言。
- Hero sync：允许合法内容寻址头像，并校验 Camp ID、实际图片哈希、资源存在及尺寸；同步工作流生成并提交匹配的本地播出原画与 manifest。未删除资源一致性检查。

## 操作变化与限制

下一局开始后，赛后面板不自动留在旧报告；要补录旧局请选择对应历史局。当前局 commit 后会自动出现本局报告。切换报告需重新选择截图，避免跨局混用；校准与队伍资料不删除。开播清单可展开，人工勾选只代表人工核对，不等于自动检测成功。

本阶段没有完成真实遮挡准确率、元流之子真实样本验收、费用预算、Webhook 独立通知或完整生命周期重构。OBS 适配器现有地址校验只允许 loopback，因此远程 OBS 地址会被拒绝；不要将录制容量显示当作远程磁盘测量。
