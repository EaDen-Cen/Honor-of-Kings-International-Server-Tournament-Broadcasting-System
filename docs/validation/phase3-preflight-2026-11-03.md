# Phase 3：真实预检与导播流程

复用现有 OperatorGuide、可保存的 DockWorkspace 布局、共享采集流与 OBS/Recovery API。没有添加第二套比赛生命周期或独立比赛状态；阶段仍由 Store 中的 BP、commit、比分和历史推导。

## 操作

1. 在 Control 顶部展开本局开播清单。自动区查询 Node、WebSocket、共享采集、OBS 场景与录制、实际录制磁盘及备份。
2. 核对查询时间；修改 OBS 或备份后点“刷新实际状态”。WebSocket 和共享流随本页连接更新；其他结果是带时间的查询快照，不是连续监控。
3. 人工核对 P1–P5、赛制、BP 画面/ROI、音频、Overlay 与公网访问。人工勾选不会改变自动区结果，完成勾选后仍可查看自动区；收起清单后展开即可复查。
4. 可使用紧急跳过继续赛事；展开后可见记录时间和未勾选项目，记录仅在本浏览器会话内保留。这不是服务端审计日志。切局、名单/顺序、赛制、BP 模式、ban 数或先手改变后重新核对。
5. 用既有阶段指引进入 BP、阵容确认、局内 HUD、OBS、比分/下一局、赛后与备份。既有快捷键、自定义工作区、移动端入口保留。

## 准确性边界

- OBS 请求遵循既有 Local Control 权限；平板/远端 403 显示未验证，不伪造连接成功。
- 配置的备用录制路径会显示剩余空间，但只有 OBS 返回的真实目录且非低空间才标记通过。
- 有备份文件不等于完成恢复演练；实际音视频、英雄模板内容、公网观看和 ROI 必须人工核对。
- 暂无设备就不能证明真实 OBS 录制、远端解说画面或平板触控通过。

## 验证

- 新 E2E 验证 OBS/磁盘失败 → 勾满人工项目仍失败 → 刷新查询后通过 → 重载重新查询失败，不继承旧通过状态；1/1 通过。
- 导播流程、断线/ACK、双语阶段、P1–P5 与蓝红先手键盘 BP 共 10 项回归通过（2.2 分钟）。
- 生产构建、Lint、格式检查通过（2 条既有 react-refresh warning）。新增状态查询只读，无 OBS 切镜、开始录制、外部通知或比赛写入。
