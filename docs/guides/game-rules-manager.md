# BO7 与逐局规则管理

在 Control 打开「逐局规则 / Game Rules Manager」，一次查看当前赛制的全部潜在对局。BO1/BO3/BO5/BO7 分别最多 1/3/5/7 局，先取得 1/2/3/4 胜结束。提前结束后仍保留规则计划，不再创建下一局。

## 设置规则

表格每一行是一局。先选择系列赛默认规则，再按需修改单局模式、英雄池、每队 Ban 数和跨局规则；未覆盖字段继续继承默认。国际服和国服使用现有英雄池，同名跨服英雄沿用同一稳定 ID；国服专属英雄不能在国际服选择。

- Match：原有交错 Ban/Pick。
- Normal：全部 Ban 完成后选角；0 Ban 仍有十个正常 Pick 阶段。
- Blind：没有传统 BP 阶段，Ban 固定为 0，不启动 BP 头像识别。

高级选项将两种历史行为分开：「受此前历史限制」决定本局是否检查之前的 Global/Player BP；「贡献后续历史」决定本局已确认实际阵容是否限制后续局。它们不是同一个全局开关。关闭英雄记录的盲选局不贡献英雄历史。

可以复制上一局、复制指定局、统一尚未开始局的规则、批量修改英雄池/Ban 数、将某局设为盲选或恢复继承默认。已开始和已完成局不会被普通批量操作修改。保存前检查影响的局数和差异；只有服务器确认后才显示保存成功。断线或冲突时重新载入服务器规则再修改。

规则模板保存在当前浏览器，可导入/导出 JSON。导入仅编辑计划，不写入比赛结果、英雄历史、选手资料或凭据；仍须保存并通过服务器验证。

## 盲选局操作

进入盲选局后点击「开始盲选局 / Start blind game」，直接建立稳定 Game ID 和十人赛后报告，不必先填写英雄。GHUD、赛后 OCR、人工统计、胜方确认、比分和下一局保持可用。

不记录英雄时，BP 记录为空，历史/Overlay 显示盲选提示；赛后行的英雄未知，不能借用上一局英雄。需要英雄资料时，启用该局「记录英雄」，再通过盲选阵容入口补录确实使用的英雄。传统 BP Pick 顺序保持为空，实际阵容单独保存。只有确认的实际英雄可以贡献历史，未识别到的槽位不产生英雄记录。

比赛结束后仍按现有流程确认胜方并更新比分，再进入下一局；胜方确认不会额外重复加分。进入下一局时自动应用该局计划，清理上一局阶段、候选、阵容和局内采样上下文。报告通过 Game ID 留在历史中。

## 中途变更与纠错

未开始的当前局和未来局可以修改。BP 第一操作或盲选开局之后，影响英雄池、阶段、历史合法性的规则锁定。已完成局保留实际规则快照，不会因为后续默认设置变化重新解释历史。

可在数学上有效时将 BO5 扩展为 BO7，新第 6、7 局继承默认规则。缩短赛制必须满足既有比分、局号与报告范围，不会静默删除历史。系列赛已经结束时不能借扩大赛制悄悄继续打；需要明确处理比赛结果。

管理员的历史贡献纠错需要指定已保存局、填写原因，并通过下游历史合法性检查。记录保存前后值和时间，可用 Undo 恢复；普通计划编辑不能改写已完成快照。

## 保存与恢复

逐局计划、当前生效规则、历史快照、纠错记录均属于服务器 MatchState，与既有存档、Undo、延迟 Caster 和备份一起保存。旧存档没有逐局字段时按原有模式、英雄池、Ban 数及历史行为迁移；旧英雄历史不会变成不贡献历史。旧客户端不支持盲选和 BO7，应统一更新 Control、Caster 和 OBS 浏览器页。

升级前保留备份；若需降级，先恢复升级前的备份。新版 BO7 / 盲选存档不能交给旧版程序继续比赛。
