# PR #69 · 赛后图形、MVP 与 GHUD 修复彩排

[文档索引](../README.md) / [导播操作指南](operator-guide.md) / [API 约束](../design/api.md)

## 赛后 Overlay 404 的根因与验证
PR #67 已在前端 `BroadcastApp` 中提供 `/overlay/postgame-compare` 和 `/overlay/game-progress`，但 Node 生产服务器固定路由白名单未登记这两项。当浏览器直接进入 `http://127.0.0.1:3001/overlay/postgame-compare?role=mid` 时，后端试图读取 `dist/overlay/postgame-compare`，返回「找不到页面或文件」。

修复：`server/uiRoutes.ts` 统一登记所有 SPA 内部 HTML 路由，前端仍复用已有 `dist/index.html` 和图形组件。步骤：更新仓库 → 在 `vite-project` 执行 `npm run build` → 停止旧进程并重启 3001 服务器 → 浏览器或 OBS 打开以下地址：
- `http://127.0.0.1:3001/overlay/mvp`
- `http://127.0.0.1:3001/overlay/postgame-compare?role=mid`（角色可改 clash/jungle/mid/farm/roam，雷达就在此页）
- `http://127.0.0.1:3001/overlay/game-progress`

这些图形只显示已有 `PostGameReport` 的真实数据；未准备报告、无经济点数或雷达双方指标不足时留空或明确提示。不是缺少 URL 的错误。2026-10-14 更新：MVP 优先选手照片，否则复用底部横排英雄裁切焦点，按 cover 填满画框并提供缩放滑条。三项主数据按选手资料中的位置选择，下面亮点排除主数据及同类重复指标。经济进程改为对局截图自动提取的优势曲线，横向零线与右侧纵轴形成横 T 型；截图估计值保留原图证据。没有可信官方评分时不计算伪官方评分。

## GHUD 2026-10-19 新版 · 轻量赛事顶栏与 OBS 图层顺序

旧版 1920×1080 GHUD 的四周不透明遮罩（顶部 146px、左 210px、右 250px、底部 280px、左上角假地图）遮挡大量实战画面，已由紧凑顶栏取代。此版本是参考 KPL 职业转播的信息层级进行**原创设计**，不是官方 UI 素材或精确复刻。

1. OBS 先放置真实观战游戏画面源，再在上方放置 `/overlay/game-hud` 浏览器源，设置 **1920×1080**，二者对齐，不要二次拉伸。
2. 默认 **Compact**：只绘制顶部 **99px** 高的信息带（65px 队名/比分/时间 + 34px 经济/推塔/资源状态），其余像素透明。真实小地图、游戏画面、两侧原生英雄与底部技能/回放区**全部保留**，不再绘制“地图源未连接”占位。
3. 可在 Control →「局内 HUD」→「密度」选 **Full**，增加 32px 高的十名英雄头像/选手 ID 小条，合计顶部 **131px**；不出现左右侧栏。
4. 旧版赛事源顶栏可能与新版 HUD 重叠。OBS 中应优先使用游戏观战的干净画面/单独裁切原生顶部信息，再把 HUD 顶栏叠上去；**不要**用大面积遮罩盖住真实地图或底部游戏画面。若客户端无法单独隐藏顶部原生 UI，须按该客户端实际布局现场检查重影。
5. 本次仅调整 GHUD 的呈现层及新局默认密度，不更改 OCR 的七项 ROI、可信阈值、数据状态、BP 及赛后报告。OCR 不可靠时应人工冻结/校正，禁止将占位数字当作赛事官方数据。

此为**开发候选**，需要真实 OBS 浏览器源、游戏观战窗口与持续录制验证；构建通过不代表画面绝无重影。

## GHUD OCR 的七字段校准
1. Control →「局内 HUD」→「GHUD 顶栏识别」；默认复用 BP 窗口。未连接时点击「连接 BP 窗口（全模块共用）」，已连接时无需再次选窗。截图仅可做离线验证，不能启用截图自动播出。
2. 原始窗口含标题栏或黑边时，展开「框选游戏内容」，点击「预览原始画面并框选」，直接圈出 16:9 游戏画面；可拖动框和四角调整。整页结算、单字段 OCR 和 GHUD 共用此内容框。
3. 点击「预览当前帧」，在预览区域选择 **游戏时间、蓝/红方人头、蓝/红方经济、蓝/红方推塔**七个字段，然后拖框只包围数字，支持拖动和角点缩放。
4. 按「保存选框并确认可采样」后，手动采样两次，逐行检查 OCR 原文本、置信度及已经核验的字段。数据过期、不合理跳变、两帧不同画面 ROI、时间未前进或人工冻结均不应写入正式 UI。
5. 只有确认真实 UI 上七个数字可靠后，才可选择每 5 秒轮询或自动播出。切换共享源、调整游戏内容框或修改 ROI 会自动关闭自动播出，必须重新预览并确认。七个 ROI 的草稿存放在**本浏览器** localStorage，不随服务器自动备份、跨端同步。
6. 若游戏 UI 改版、语言不同、图标遮挡、人物头像闪动或经济缩写文字与校准预期不一致，及时取消自动发布，保留人工录入并使用原冻结/Undo。

## 边界、测试和下一步
单元测试覆盖后端路由表、ROI 数量/边界/重叠、跨 ROI 配置无法合并、静止回放时钟与既有时间趋势。生产 build/ESLint/CI 的绿灯不能证明真实十人比赛和 OBS 画面没有漏边。必须由导播提供相同观战界面的完整截图或录屏来确定所有 HUD 原生部件是否被遮挡；官方赛事图只作布局参考，不表示当前版本能读取其内部数据。


**本次回归纠正：** 合成 HUD 真实数值样本确认，蓝方经济在纯 OCR 模式下曾被误读为十倍（1.5K→15.0K）。因此保留针对含明显青色原生 HUD 强调色的自适应背景抑制；没有青色强调色时使用原图，不对新 UI 强制蓝方遮罩。任何模式仍需真实七字段校准、两次检测与人工审核，这不构成官方 UI 通用识别保障。


**旧版全遮挡安全区已废弃（历史记录）：** 顶部 146px / 左 210px / 右 250px / 底 280px / 假地图。新版改为仅顶部 99px（Compact）或 131px（Full）的原创建模赛事信息条，其余 1080p 画面透明；仍需核对原生顶栏重影。


**对位页面交互**：五个角色标签已改为可点击的链接（OBS 自动刷新仍可使用静态 `?role=` URL）；不影响 API 读取。同一 URL 在没有准备有效局十人报告时会显示清楚的缺失提示，而不是透明空白。


## 2026-10-13 / PR #70 — 赛后数字 OCR 恢复截图直接框选

用户实际反馈：在「选手评分 / Rating · 补录与识别」中，右侧浏览器打开保存的原图出现纯黑画面，十名选手大部分候选为 0% 或「—」。定位发现旧「单字段 OCR」依赖独立隐藏 video 流，既**不能复用结算整页工具所上传的静态截图**，也没有直观的手工拖框工作区；默认的百分比矩形不保证命中数值，导致保存黑色/空白裁图。这不是游戏评分自动识别已完成的证据。

更新后的操作顺序：

1. 在 Control 先提交有效局并建立十人报告。「结算整页采集」上传 PNG/JPEG 截图，或在「单字段 OCR」选择共享游戏窗口/截图。两项共用**本次浏览器会话的截图对象**；无需另外打开 `/uploads/player-portraits/…png` 才能校准。
2. 展开「单字段 OCR · 直接在结算截图框选数字」，选择对应的结算页（如「数据」）和字段（如「游戏评分」）。点击「预览 / 刷新当前画面」，对当前游戏/截图帧进行冻结，避免识别时画面又跳到另一页。
3. 在完整的 **16:9 图像预览**中选中蓝方/红方某位选手，直接鼠标拖动，**只包围这一位的数字**。画面上显示对应 B1–B5、R1–R5 的彩色框，下面显示所选框的实际裁图预览。拖动已有框可移动，拖动四角可缩放；预览缩放后继续用鼠标精调。
4. 如果结算页同一队五个数字**间隔规律且位置不变**，可点「按行距复制本队 5 个框」。目前使用实际已知的 1920×1080 旧模板行距 **130 像素**生成框；**务必目视核对每一框，不要把 BP 顺序和结算页行顺序混同**。不熟悉版式时，逐人框选更安全。
5. 点击「识别当前选手」即可只发一个 OCR 裁图；也可「识别所有已框选选手」。现在不要求一定配置好十个人才允许开始。服务端根据**显式的十人报告 rowId**绑定每张裁图，不允许凭数组下标猜测剩余的选手。
6. 识别的数值、置信度和「裁图」链接会显示在对应选手旁边；只有置信度达到 85% 且不会覆盖已人工确认/既有可信冲突数据时，才会出现在「应用已核验候选」操作中。黑色/纯色裁图在前端和服务端都会被拦截，不再保存伪证据或假装读到了 0。
7. 评分仍可以手工录入，MVP 仍由赛事方投票决定；本功能**不会计算伪造的游戏评分或用未知数值填 0**。若整张截图原本就是黑屏，需要更换为游戏真实截图/窗口，并在「预览」中确认，而不是靠猜测像素坐标。

**存储/同步**：已确认的当前字段裁图区域沿用浏览器 `localStorage['hok-post-game-regions-v1']`，以结算页/指标/玩家行号分别保存。截图图像本身只在当前网页会话内分享，不通过共享 token 同步到另一台设备；换电脑要重新上传。实时窗口获取仍遵守浏览器授权和应用原有 `sharedWindowCapture`。系统仍不承诺 2026 年所有国服/国际服页面能固定定位 OCR，需要提供真实样本继续校准。

此分支增加了「单人/部分选手截取和身份绑定」「重复/非法 rowId 阻断」「同队 ROI 行距复制不影响对手」等单测；实际游戏截图/OBS/Windows 浏览器兼容性需要用户本机截图验证，以最新 CI SHA 记录自动化结果，不等于已跑完整十人直播验收。


**精细框选**：预览增加 100% / 150% / 200% 缩放，坐标始终相对冻结的整张游戏画面，不会因屏幕滚动或浏览器大小不同而改变 ROI。预览冻结图改用无损 PNG，避免重新编码 JPEG 导致小数点边缘损失。


**黑屏保护**：整页结算与 GHUD 入口会阻止基本纯黑的窗口截图进入 OCR，直接提示选择正确游戏窗口/图片。旧黑屏证据文件仍可能存在于用户本地，但新的空白证据不再由这些入口产生。
