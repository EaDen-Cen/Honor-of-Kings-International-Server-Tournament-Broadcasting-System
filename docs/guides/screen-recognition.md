# Auto BP / 屏幕识别指南

## 结算数据：按页面采集（2026-10-13 修正）

在「赛后数据与 MVP」准备报告后，默认复用 BP 窗口。在游戏里切换结算页，点击「采集整页」，核对十人映射与数据后应用。逐页上传截图也会保留此前页面草稿。表内可直接修正数值；逐字段框选收在「高级修正」，仅用于模板位置不合适时校准。含模拟器标题栏的画面先框选游戏内容。

| 游戏页面 | 获取的数据 |
| --- | --- |
| 结算总览（返回房间页） | KDA、精确总经济、字母评级 |
| 数据 | 输出、承伤、总经济及三者占比、参团率 |
| 输出 | 输出、输出占比、伤害转化比 |
| 生存 | 承伤、承伤占比、每死承伤 |
| 发育 | 总经济、野怪经济、补刀数及各自占比 |
| 战绩 | KDA 及各项占比 |
| 团队 | 参团率、控制、治疗、对塔伤害及后三项占比 |
| 对局 | 两队 KDA、总经济、推塔、五类资源数量及经济优势曲线 |

经济占比是总经济下方的百分比；伤害转化比是 0.8、1.5 等小数倍数。7.6k 带圆整精度，7589 是精确经济：精确值可以完善相容的圆整值，圆整值不能反向覆盖可信精确值；人工修正继续受保护。B/A/A+/S 等字母评级单独保存，不换算为数字游戏评分，四位数经济也不能当作评分。

提供的总览样本中，部分 A+、S 的字体 OCR 置信度不足，需在评级下拉中确认；低置信度数字同样留在草稿，可直接在该行修正。

**经济优势曲线（2026-10-14）：** 采集完整「对局」页后，程序读取正/负刻度、时间标签和白色圆环标记，在页面内预览曲线。确认「我方」对应蓝方或红方，再点击应用，曲线与本页汇总一次保存。OBS `/overlay/game-progress` 显示双方经济优势差：零线横穿中间，右侧为纵轴，上蓝下红，形成横 T 型；不再画两条累计总经济曲线。时间按实际标签分段校准，差值和时间是截图像素估计，不是精确游戏遥测。缺失标记、刻度不一致或置信度不足时保留已保存曲线。

**MVP（2026-10-14）：** 选择选手后，位置和照片按该选手的队伍身份读取，不按 P1–P5 默认位置推定；资料里更正位置后旧报告展示同步使用更正的位置。图片优先选手照片，其次横排英雄裁切焦点，图片加载失败仍可回退。默认最宽填满，可用「MVP 图片缩放」滑条调整。三个大框按位置显示主指标（对抗：承伤/参团/输出；打野：转化比/参团/输出；中路：输出/占比/参团；发育：输出/转化比/对塔；游走：参团/治疗/控制）。下面最多三个亮点按同队相同指标比较，排除主指标及同类重复项；没有可信数据则留空，不自行评定 MVP。

**曲线框选适配修正：** 曲线先定位图表边界，再读取标记和轴标签，适配框选后仍为 16:9 的缩放、平移和重采样。无需把端点对齐到固定像素。鼠标遮挡末尾标记时，保留可见点并显示提示，不补造被遮挡的点；希望采集到最后时刻，可将鼠标移开曲线后重新采集。部分截图曲线不会覆盖已保存的完整曲线；可信完整采集可以补全部分曲线，播出页也标明部分结果。正负刻度会分别重读弱结果，不因另一侧读数可靠而跳过弱侧校验。

> v1.0.0 Release Candidate：Auto BP 与 Player ID 自动排序已进入发布准备状态；Simulator 的 BP 压力测试在约 1.5–2 秒选角窗口下可稳定出结果，Player ID 完整核查最佳实测约 1.8 秒。以上是测试环境结果，不代表真实比赛设备 SLA。

v1.0.0 的 Auto BP 采用**浏览器窗口采集 + 18 个独立槽位校准**。旧的 Windows 物理像素兼容采集不再作为正常操作入口。

## 1. 开启屏幕识别

在 Control 的比赛设置中，将 BP 输入模式切换为 **屏幕识别**。

Auto BP 主工作区会显示：

- 采集窗口连接状态；
- 游戏/BP 预览；
- 当前 phase；
- 当前 Ban/Pick 槽；
- 识别候选与相似度；
- 空 Ban 状态；
- 立即识别；
- 手动确认当前最高候选；
- 自动监视。

低频的校准、预设和手动英雄池默认折叠，避免比赛时占用主操作区。

## 2. 选择采集窗口

点击“选择/更换采集窗口”，在浏览器提供的共享窗口列表里选择：

- 真实 HOK BP 窗口；或
- BP Simulator 的采集页。

页面只处理你主动选择的共享画面。Control、Caster 和 Overlay 不会自动抓取桌面其他内容。

## 3. 18 个独立识别框

Match BP 共有：

- 蓝方 B1–B4；
- 红方 B1–B4；
- 蓝方 P1–P5；
- 红方 P1–P5。

合计 18 个独立框。

展开 **识别框校准与工具** 后，可以逐个选择槽位。推荐进入全屏精细校准：

- 拖拽重新框选；
- 方向键移动 1 像素；
- Shift + 方向键调整宽/高；
- [ / ] 或界面按钮切换槽位；
- + / - 调整校准视图缩放；
- Enter 前往下一个槽位。

框应该尽量只覆盖头像本身，避免边框、选手 ID、动画文字或相邻槽位进入识别区域。

## 4. 保存和载入 18 框预设

校准完成后，在校准工具内部展开 **18 框位置预设**。

一个预设会保存全部 18 个框的 x、y、width、height。坐标按采集窗口的相对比例保存。相同 UI 布局下，单纯移动窗口或改变普通窗口尺寸通常可以继续复用。

建议按用途命名，例如：

- 赛事机 1080p
- Simulator
- 比赛服 16:9

预设支持保存为新预设、载入、用当前 18 框覆盖、改名和删除。

预设保存在 Director 浏览器的 localStorage。换电脑、换浏览器配置或清理站点数据后不会自动同步。

## 5. Hero Pick 识别与锁定

### 普通 Pick、双 Pick、阶段边界与最后一手

程序先稳定识别当前 Pick 英雄，再确认**当前选手英雄头像底部菱形内的勾号**连续出现两次。不会观察下一位是否预选，也不会把高亮或亮度变化当成锁定。

连续同队 Pick 仍作为同一个 Turn，例如红方 P1 + P2、蓝方 P2 + P3、蓝方 P4 + P5。每个位置分别检查英雄与勾号；两个位置都满足条件后才整组审核/提交。阶段边界和最后一手使用相同规则。

头像框仍只框英雄。程序另外读取向下延伸约 30% 的小块画面用于勾号检测，不把这块区域加入英雄匹配。预选时出现头像但没有勾号，会继续等待；勾号被遮挡、裁掉或过小则使用人工确认，不根据其他位置猜测。

## 6. 自动锁定没触发时的人工 fallback

如果你已经在游戏里看到英雄锁定，但程序仍显示等待锁定，不必卡住整轮比赛。

点击：

**手动确认当前最高候选**

程序会使用**最近一次扫描**中的最高相似度结果：

- 单选：打开当前最高候选；
- 双选：分别取当前两个槽位的最高候选，作为一个英雄组打开审核；
- Ban：有候选即可进入人工审核；低分不会自动通过。

若正确英雄未进入前五候选，审核下拉框可手动选择完整英雄池中的其他英雄。

这只是跳过“锁定状态自动判断”，不会跳过最终人工审核，也不会绕过服务器的 phase、重复英雄和 BP 规则检查。

## 7. Ban 识别

Ban 槽在实际画面中是圆形头像，因此 Ban 使用单独的圆形 mask，减少方形模板四角造成的相似度损失。

正常 Ban 需要当前头像右下角的明确白色锁形标记，结合锁环和钥匙孔结构检查，并连续确认两帧。局部指纹变化、计时器、头像高亮或下一阶段画面都不能替代锁形标记。圆形匹配会排除锁标覆盖的右下角，模板也做同样处理。

相似度是图像相似度，不应理解为严格的统计准确率。实机仍应使用真实比赛素材做一次校准。

## 8. 空 Ban

**空 Ban 仅由导播手动确认。** 低分英雄、未知头像、空槽、计时到期或局部画面变化都不会自动弹出空 Ban 审核，更不会自动提交。

真实英雄（如影）与模板不匹配时必须保留为“未知”，不能被当成空 Ban。确认游戏已跳过本次禁用后再点击 **空 Ban / 跳过本次禁用**。后续自动空 Ban 需要单独的实机正面证据，当前没有启用。

## 9. 自动监视

打开 Auto Watch 后，程序会持续扫描当前所需槽位。

默认由导播审核候选；若显式启用高相似度自动输入，满足阈值、稳定帧和锁定条件的英雄可自动提交。空 Ban 仍人工确认。出现审核弹窗时自动扫描暂停，确认或拒绝后继续。

比赛中建议一直保留游戏预览、当前 phase、当前槽位、当前候选和识别状态。校准工具和手动英雄池平时保持折叠即可。

## 10. Player ID / P1–P5 自动排序

开局时 Player Slot Alignment 与 Auto BP 共用同一个采集窗口，不会额外要求导播重新选源。

1. 双方赛前 5 个 Player ID 必须已填写且各自唯一。
2. 默认 ID 区域从 P1–P5 Pick 头像旁自动推导；如真实 UI 不同，在“高级：选手 ID 区域校准”点击“预览 BP 画面并框选 ID”，直接画框、移动或拖四角缩放。
3. 10 个 ID 区域可以保存为**独立命名预设**，不会覆盖 18 个英雄 Ban/Pick 识别框。
4. 后端使用常驻英文/简中 OCR worker：先跑 soft 快速候选，只对未通过的队伍追加 threshold 170/190。
5. 每队在已知 5 人 roster 中求 120 种一一映射；双方都可信时一次原子提交十个槽位。
6. 如果单帧总有某一个槽位略低于阈值，但同一个排列连续出现，程序可合并两帧各槽位最佳匹配度；仍需满足每槽 0.80、平均 0.90、margin 0.06，不会降低安全线。
7. 手动采用建议或交换顺序会暂停自动覆盖；之后点击 **恢复自动识别** 即可重新开始自动核查。

UI 显示的是 roster-match confidence，不是 Tesseract 原始字符 confidence；原始 OCR 文本、confidence 与预处理 variant 仅用于调试 tooltip。

## 11. 同一 BP 窗口与统一框选

Auto BP、Player ID、换英雄、赛后整页/单字段 OCR 和 GHUD 默认共用同一条 BP 窗口采集流。只有显式连接或在 BP 更换窗口时才打开浏览器选窗器；其他模块的“使用 BP 窗口”直接复用。取消更换保留原窗口，换窗会释放旧流并清理过期候选。

需要去掉标题栏/黑边时，在赛后或 GHUD 展开“框选游戏内容”，预览原始画面并圈出 16:9 内容。赛后与 GHUD 共用该内容框。各 OCR 区域均直接在对应预览上画框、移动和拖角缩放，不再填写 x/y/width/height。换英雄复用 BP Pick 框；BP 与 ID 的预设继续保留。改变采集源或校准后，请重新预览 GHUD 并确认字段位置。

## 11. BP 完成后的换英雄检测

BP 结束后，最终阵容区域会持续扫描蓝/红双方 P1–P5。

识别时每支队伍**只在本队已经 Pick 的五个英雄里匹配**，然后求一组不重复的最终分配。

自动模式：

1. 检测到最终阵容与当前 assignment 不同；
2. 阵容连续稳定；
3. 达到最低识别质量；
4. 自动发送最终阵容同步。

如果同步没有及时发生，可以点击 **立即识别并应用换英雄**。

如果画面本身无法可靠识别，最终仍可使用每个选手旁边的下拉框手工交换。

换英雄只改变最终英雄归属，不改写原始 Pick/Ban 历史。

## 12. BP Simulator

不需要真实游戏也能测试。

Windows：

~~~text
start-bp-simulator.bat
~~~

启动完成后命令窗口会自动关闭，Simulator 在后台运行。

控制页：

~~~text
http://127.0.0.1:5173/tools/bp-simulator-control
~~~

采集页：

~~~text
http://127.0.0.1:5173/tools/bp-simulator
~~~

控制台按 **选手 ID 排序 → BP 模拟 → 角色交换** 三种模式独立测试，支持 Match / Normal BP、蓝/红先手、单选与双选、空 Ban、Pick 高亮与锁定、自动推进，以及最短/最长随机选角等待时间。BP 自动脚本可在思考期间随机切换当前预选英雄，最后保留稳定候选窗口；锁定后的 cue 保留时间可单独设置，默认约 1.1 秒，不再使用过短的 120ms 测试窗口。

Simulator Control 顶部提供 **从 Control 同步模拟器数据**：

- 选手 ID 排序：读取双方名单和当前 P1–P5 排序；
- BP 模拟：读取 Control 当前模式、先手方、已完成 Ban/Pick 与 phase；
- 角色交换：要求 Control 已完成且未提交本局，直接把当前 `blue/redAssignments` 作为 Ground Truth 基线，不必重新造一套 BP。

这是**单向只读同步**，不需要开启“Control 联动测试”，也不会修改 Control。需要把 Simulator 人工配置反向装入 Control 时，才使用原来的联动基线按钮。

换英雄测试开始计时后会锁定队伍/P1/P2选择，直到 Control 同步目标 assignments，避免测试过程中再次交换导致 Ground Truth 改变。旧 `hok-bp-simulator-state-v2` 中的英雄 ID 也会在首次打开新版 Simulator 时迁移到当前 release-order ID。

结束：

~~~text
stop-bp-simulator.bat
~~~

## 13. 现场验收建议

每个真实比赛版本至少保留一组测试素材，重点检查：

- 常用英雄 Pick；
- 圆形 Ban；
- Ban 锁定前/后；
- 双 Pick；
- Pick→Ban 边界；
- 最后一手；
- 空 Ban；
- BP 完成后的英雄互换；
- 双方 P1–P5 随机排序、英文/简中/数字混合 ID；
- 手动采用建议后恢复自动识别；
- 1.5–2 秒极限 BP 脚本是否仍能稳定锁定。

如果游戏更新导致 UI、头像裁切、光效或比例变化，优先重新校准 18 框，再判断是否需要调整识别算法。

## 自动输入阈值与性能

在比赛设置的屏幕识别高级项中配置自动输入及 50%–100% 阈值。分数是头像相似度，不是准确率。只有稳定且已锁定的英雄/双选组、每位分数严格高于阈值时才自动输入；空 Ban 仍需人工确认。服务端继续验证修订号和 BP 规则。

识别器同时比较输入画面与模板的多种裁切，包含 50%–60% 的偏移面部视图，适配游戏头像比图库头像更放大的情况；深度裁切降低分数，避免局部相似颜色取代完整头像证据。Ban 校准边界显示为椭圆：正方形框对应圆，宽高不同时对应椭圆。匹配先保留完整椭圆视图，再比较缩放视图，并排除右下锁标；框外背景不参与完整视图的英雄匹配。原有框坐标和预设可继续使用，请让椭圆边界贴合头像，避免把邻位头像纳入。锁标检查读取未遮罩原图，与英雄匹配分开；浅色头发粘连时补充局部锁环、锁体及暗色钥匙孔验证，不能把稳定头像当作锁定。自动稳定至少需要 55% 相似度、第一/第二候选至少 6 个百分点的差距；55%–65% 需三帧，65% 起需两帧。分数不足或候选接近时保留人工选择，重复错误候选不会因等待更久自动变成可信结果。

完全相同的头像、锁标裁图、形状和允许英雄池可复用证据缓存；缓存上限 64 项，失败不会保留。接口另外返回明确的 `lockCue`，指纹和亮度仅保留兼容，不作为锁定依据。

遇到误识别，点击 **保存识别样本**，本地下载 `hok-hero-recognition-sample.json`，包含最近最多 18 个头像/锁标裁图、阶段、区域和候选，不包含访问凭据，也不会自动上传。请检查文件后再分享，并注明正确英雄与是否锁定。开发者可在本地样本中标注 `expectedHeroId` / `expectedCue`，设置 `HOK_HERO_RECOGNITION_SAMPLE` 后运行回归测试；私有实机图片不进入仓库。

Simulator 可读取 Control 的模式、先手与规则历史；未连接服务器时按普通 BP 模拟。随机抽取按 BP 顺序检查重复、跨局限制与元流之子规则。随机等待只用于选角思考；可在锁定前多次随机切换预选英雄，并保留最终稳定窗口。锁定 cue 默认保留约 1.1 秒且可调整；Control 自动监视约每 250ms 发起下一次串行扫描，因此 3–6 秒压力测试仍有足够的稳定帧与锁定确认机会。采集画面以固定 1600×900 坐标整体缩放；窗口大小改变后仍应核对采集框。 Simulator 控制台的“采集画面尺寸”可随时单独调整 Pick 头像（48–104px）与 Ban 位（24–64px）；设置实时同步到采集页并持久化。Pick 大小用于 BP、换英雄和 Player ID 测试，Ban 大小只在 BP 测试画面显示。


## 0–5 Ban 与国服独有英雄（开发 PR #68）

屏幕区域现在支持 20 个独立可保存槽位：蓝/红各 5 Ban + 5 Pick。低于 5 Ban 的模式只启用当前赛制中出现的槽位；4 Ban 旧预设的前四个 Ban 区域保持兼容，第五个 Ban 未有经过实机测试的默认校准，必须手动精确框选。0 Ban 不触发 Ban 锁识别。当前头像识别训练材料源于国际服的已有英雄，国服独有英雄的识别模板及国内客户端布局**没有完成同步和验收**；对于国服赛事应优先使用手动 BP 和候选复核，不要启用未经验证的自动输入。参见 [双服 BP 规则指南](hero-pool-and-ban-rules.md)。


**国服自动录入保护（PR #68）：** 切换到 `cn` 池时，高相似度自动应用 BP 将自动关闭，后台保存设置也会强制禁用自动输入；因为国服独有英雄图像和第五 Ban 区域尚未完成实机训练/验收。可继续通过人工选取或人工核对候选操作；待官方图像模板与真实现场验证充分后，再单独实施开启规则。

数字采集目前使用独立英文 OCR 模型，已用实际截图验证 `k/K`、百分比、小数与对局时间。数值解析器支持“万”，但模型尚不能可靠识别带“万”的截图；本地渲染样本出现了低置信度误读，未达到自动应用所需的 0.85。遇到这种单位请人工核对并填写完整数值，不要仅凭当前 OCR 草稿发布经济数据。玩家 ID 的简中模型独立运行，不代表数字采集已经通过中文单位验收。

十人页面首次采集时核对「十人页面左侧队伍」。默认左蓝右红；如果游戏友方实际在红方，请选择红方。此选择按本局报告保存，数值仍按原画面行读取，身份按实际队伍匹配。改变方向会保留各页数字草稿与证据，清除旧身份绑定，请重新核对十人后应用。对局汇总没有十人名单，仍单独确认「我方」对应哪一队。
