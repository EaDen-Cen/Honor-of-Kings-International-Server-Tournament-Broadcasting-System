# 比赛操作指南

> **v1.0.0 Release Candidate**：正常比赛主链路以 Draft Overlay、Caster、Auto BP、Player ID 对齐和最终阵容为准。**局内 HUD 仍处于测试阶段**，不要把它当作唯一官方比分来源。

## 比赛流程与规则

1. 载入两支队伍，设置 BO、BP 形式（每队 4 Ban 或 2 Ban）、规则及先手方。选手 BP 需要十个非空且唯一的选手 ID。
2. 普通 BP 不限制跨局选人；选手 BP 根据选手 ID 追踪已用英雄；全局 BP 根据稳定队伍 ID 追踪已用英雄，并禁止 Ban 对手此前有效局已使用的英雄。
3. 按当前阶段录入英雄，结束后用“英雄归属校对”核对位置。
4. 裁判确认比赛有效后，点“确认本局有效”保存历史，再更新比分，最后“开始下一局”。确认有效不会自动加分或清空画面。
5. 换边须在本局 BP 开始前执行，可选择交换队伍显示位置，或位置不变仅交换蓝红方。BP 先手独立设置，换边不自动改变先手。
6. 无效且未提交的 BP 可重置选禁；已有有效历史继续保留。重置整场清比赛和历史，不删除队伍库；Undo 可撤回比赛操作，解说端比赛进度仍按延迟显示。

规则在首次选禁后锁定；已有有效历史后不能直接更换规则。现场仍可修改选手 ID、分路和照片，但必须通过当前 BP 资格验证。底部横排与左右竖排 Overlay 均按 1920×1080 接入 OBS。

## 导播录入

### 手动 BP

- 手动模式保持左右工作区：比赛监视与操作 + 当前阶段英雄选择。
- `/` 或 `Ctrl+K` 聚焦搜索，`Esc` 清空；搜索结果只有一个合法英雄时，`Enter` 提交。
- 收到服务器确认后才清空搜索并重新聚焦。保留 revision、单条 pending、防重复、输入法组合输入保护。

### Auto BP

- 屏幕识别模式把 Auto BP 作为主工作区；手动英雄选择器默认折叠为备用入口。
- 开局会并行进行 **P1–P5 Player ID 自动对齐**。双方 10 个 ID 使用本地 OCR + 已知 roster 全局匹配；双方可信时原子更新顺序。
- 如果显示“自动复核中”，程序会继续后台核查；同一排列连续出现时可合并两帧边缘证据，但仍保持原有安全阈值。
- 人工采用建议或手动交换会暂停自动覆盖；需要重新交给程序时点击 **恢复自动识别**。
- 低频的 18 框校准与预设默认折叠；Player ID 还有独立的 10 区域预设，不会覆盖英雄 18 框。比赛时只保留采集画面、phase、槽位、候选、识别状态和常用按钮。
- 自动锁定判断没有触发时，可点击“手动确认当前最高候选”，直接用最近扫描的最高相似度单个英雄/英雄组进入人工确认。
- BP 完成后最终阵容区继续监视 10 个 Pick 槽；稳定检测到英雄互换时自动同步，也可“立即识别并应用换英雄”。
- Auto BP 的详细锁定规则、空 Ban 和校准方式见 [屏幕识别指南](screen-recognition.md)。

比赛设置使用弹窗；英雄数据与图片设置采用可搜索头像网格，不再使用超长英雄下拉列表。

## 英雄数据与图片设置

“英雄数据与图片”窗口左侧使用可搜索头像网格：

- 输入中文名、英文名、alias 或拼音声母会实时过滤；
- 点击头像直接切换当前英雄；
- 默认只渲染前 48 个匹配项，可继续加载或显示全部；
- 英雄数据、头像地址、全身图地址和 Panel/Side 裁切仍按当前英雄保存。

这套选择逻辑与比赛中的 Hero Picker 分开，不会提交 BP 操作。

### Panel / Side 构图保存位置

“英雄数据与图片”中的 Panel / Side 裁切点击保存后，会先作为 `heroArtOverrides` 写进当前服务器的 `data/match.json`。这保证刷新、重启与备份都能恢复，但 `data/` 属于本机运行目录，**不会自动同步到 GitHub**。

如果这次裁切是你希望以后所有比赛机都共用的正式构图，在调好后运行：

```text
sync-hero-crops.bat
```

或：

```powershell
npm run hero:crop-sync
```

它会把 Panel / Side 的 x/y/scale 写入 Git 跟踪的 `src/data/heroArtFocusOverrides.ts`。随后检查 Git diff 并正常 commit/push。该流程不会把比赛数据、队伍、选手或访问凭据带进仓库；`useLegacyImage` 也继续保持为运行时选择。

## 选手照片

比赛设置与队伍资料编辑中均可直接上传 PNG、JPEG、WebP，单张不超过 5 MB。
预览显示加载状态与实际地址。比赛设置内上传后需要保存设置；资料库内上传后需要保存队伍。
比赛中仍可更改选手 ID、分路与照片。未选英雄时显示照片，选中英雄后使用既有英雄揭示动画，撤销后恢复照片。

上传仅允许 Control 身份。服务器检查格式、文件内容、尺寸字节上限并生成随机文件名。
照片运行时提供，不需要重新构建网站。清空引用不会删除实体文件。

## 队伍资料库

入口：比赛设置 → 队伍资料库 → 管理队伍资料。

1. 新建队伍，录入队名、队标地址、五名选手、分路与照片，然后保存。
2. 新比赛中分别选择蓝红方队伍并载入，再设置 BO、BP 规则和先手等。
3. 载入会替换阵容并刷新设置表单，因此会要求确认丢弃未保存的比赛设置。
4. 载入的是独立副本。现场替补或阵容调整并保存比赛设置，不会覆盖资料库。
5. 需要长期保留修改时，明确选择“更新已保存队伍”；“另存为新队伍”创建独立身份，随后可载入。

资料库支持搜索、新建、编辑、删除和分别载入蓝红方。
服务器拒绝同一队伍占据双方；当前 BP 已开始、存在有效历史或已经提交本局时，禁止载入其他队伍。
已载入队伍使用永久 UUID 身份。普通设置忽略客户端传来的身份更改，换边后全局 BP 限制继续跟随队伍。
删除资料库条目不影响当前比赛、有效历史或图片文件。重置整场比赛不删除资料库。

## 替补与快速换人

- 在“管理队伍资料”中，找到“替补名单”，可保存最多 20 名替补的 ID、分路和照片；上传方式与首发一致。
- 比赛设置 → 对应队伍 → 快速换人：选择选手资料来源、已保存选手和目标位置，点击“填入选手资料”，再保存比赛设置。
- 已从资料库载入的队伍默认使用自己的资料；手动创建的比赛也可选择本队资料来源，不需要重置比赛或替换队伍身份。
- 可选项包括资料库中的首发与替补，方便将原首发换回。
- 换人只修改目标位置的 ID、分路、照片。其余比赛设置保持表单原值，由原有服务器校验统一提交；解说端 BP/比分继续遵循延迟时间线，选手资料实时更新。
- 全局 BP 历史跟随队伍；选手 BP 仍按选手 ID 检查历史。若新选手使用当前英雄违反个人限制，保存会被拒绝并保持原状态。
- 临时换人不覆盖资料库。明确更新已保存队伍时，未提交替补名单的旧式请求会保留原名单；旧资料库没有替补字段时自动按空名单读取。

## 实验功能：局内 HUD 与赛后 MVP

- `/overlay/game-hud` 可展示队伍、系列赛比分、当前局、人头、推塔和中立资源。
- **HUD 当前仍处于测试阶段**：局内数据主要由导播人工维护，七项顶栏 OCR 已可两次采样核验、自动采样并手动冻结字段；OBS 长时间稳定性与不同游戏 UI 版本仍未正式验收。
- 正式比赛若启用 HUD，必须同时保留官方观战 UI、人工比分记录或其他权威来源作为兜底；出现不一致时以赛事裁判/官方数据为准。
- `/overlay/mvp` 已升级为 1920×1080 全屏 MVP；系统不自动判断谁是 MVP。赛后 OCR 仍需要人工复核低置信度字段。新增 `/overlay/postgame-compare?role=mid`（五位置对位与雷达）及 `/overlay/game-progress`（经济时间线）。

## 存储与接口

默认都在 `vite-project/data/` 下：

- `match.json`：比赛、撤销、延迟时间线。
- `team-presets.json`：版本 1 独立资料库；原子临时文件写入、同步与重命名。
- `uploads/player-portraits/`：运行时图片。

指定 `DATA_FILE` 时，资料库和默认上传目录跟随该文件的父目录；可通过 `UPLOAD_DIR` 单独指定图片目录。
迁移、备份时保存整个数据目录。上传图片和资料库均不进入 Git。

仅 Control 可使用 `GET/POST /api/team-presets`、`PUT/DELETE /api/team-presets/:id` 和 `POST /api/uploads/player-portrait`。
队伍载入经现有 WebSocket `load_team_preset {side,presetId}` 操作，走原有验证、持久化、实时广播与延迟时间线。
图片 GET 不要求口令，以支持 OBS、解说页面及浏览器图片标签。

## 验证边界

新增服务器测试覆盖资料库持久化、身份稳定、复制隔离、落盘失败、载入锁定、防重复、删除保留历史与换边后的限制。
新增浏览器测试覆盖真实上传、蓝红先手各完整 18 步键盘录入、确认前保持搜索、桌面/平板/手机布局和队伍资料实际操作。

真实 OBS 内置浏览器、跨设备 Cloudflare 链路和十张实际选手照片仍需赛前彩排；浏览器自动测试不能替代这些实机验收。
一键启动与 Cloudflare 脚本保持原接口。更新服务器代码后需要重启服务；更新页面后刷新浏览器和 OBS Browser Source。

## 访问与网站设置

导播顶栏的“访问与网站设置”可保存远程访问密码（8–256 字符），同时生成各角色独立 token。已连接网页自动更新凭据；离线网页重新登录。本机 `localhost`、`127.0.0.1`、IPv6 回环连接经服务端验证后免登录，代理和转发请求不会被当成本机。不要向解说分享管理员密码，应生成 Caster 只读链接。

公网网址输入框用于保存将来的域名并打开对应页面，不会自行部署服务器。固定域名部署见运行指南。

## 识别自动输入

比赛设置选择屏幕识别后，展开“屏幕识别 · 高级选项”，启用高相似度自动输入并设置 50%–100% 的阈值。候选必须严格超过阈值，仍需通过稳定帧和锁定检查；双选需要两位都满足条件。空 Ban、低分候选继续人工审核。默认关闭，阈值默认 90%。

英雄图片设置中的“英雄数据 · 高级选项”默认收起，展开后编辑名称、分路、别名和图片来源。


## 回放优先的赛后彩排（PR #67）

不需要集齐十名玩家才能测试赛后：用游戏回放 PNG/JPEG 先准备一局有效报告，然后在「结算整页采集」确认本局蓝红双方 0–9 行分别对应的实际选手，切换六个十人数据页时沿用相同映射。弱 OCR 或行序确有变化才人工校正；映射保存在**该浏览器**，不会因为服务器备份在另一台电脑自动出现。Recap 左右队伍仍需要单独选择。

固定整页模板未找到稳定的「游戏评分」裁切位置，导播应在「选手评分」核对并填入真实评分（或使用下方十行单字段 Rating OCR 自行校准）；没有数据就保持空白。时间线在「游戏进程 · 经济时间线」逐行输入 `02:00,3500,3600` 等真实采样，2–240 点，按时间顺序提交；系统只连实测点，不从终局经济反推。三套赛后 OBS 链接见 [运行指南](getting-started.md#本机运行)；对位链接中 `role` 取 clash/jungle/mid/farm/roam。正式播出前仍须用 OBS 的 1920×1080 Browser Source 查看安全区与画面。


## 双服英雄池与每队 0–5 Ban

比赛开始前，在「比赛设置」分别选择「英雄池服务器：国服 / 国际服」与「每队 Ban：0–5」，再选「Match / Normal」和普通/选手/全局 BP。国服并**不会自动强制 5 Ban**；国际服也可以为了社区赛用 0–5 Ban。更换 BP 模式会将 Ban 恢复到该模式历史默认数（Match=4、Normal=2），之后可单独设置数量。首手 Pick/Ban 后及有效局历史产生后锁定这两个选项，防止进行中的历史阶段错位。Simulator 的 BP 模式页必须确认英雄池、Ban 数与 Control 一致，也可使用「从 Control 同步模拟器数据」自动复制。

国服候选目录尚未完整核对到 2026-10 最新官方英雄，CN-only 英雄缺少完整 OCR 模板；选择 CN / 5 Ban 后务必先校准第五 Ban 画面与头像，并用人工兜底。不要把 0 Ban 误认为巅峰对决盲选，当前 0 Ban 仍按公开蛇形 Pick。详见 [双服规则与校准指南](hero-pool-and-ban-rules.md)。


## 赛后页面 404 / MVP 图像与 GHUD 一体化彩排（PR #69）
先从最新版 `main` 执行构建并重启 3001 服务器，测试 `/overlay/postgame-compare?role=mid` 和 `/overlay/game-progress` 能够加载网页。如果没有准备当前局赛后报告，页面虽会打开但不会自动产生虚假统计。MVP 改为完整英雄立绘内缩，保证重要角色动作不被裁掉；只有可信 Rating 才显示评分卡。

游戏局内请使用 OBS 1920×1080 游戏画面 + 同尺寸 HUD 浏览器源，HUD 浏览器源要**置于游戏层上方**。不透明的顶部、边栏、底部遮罩避免新旧比分或技能控件双重出现，但需要根据实际观战窗口裁切比例核对是否漏出。系统默认遮盖原生小地图并显示地图源未连接；如需官方式地图，请在 HUD 上方再放一份游戏小地图单独裁切源，调整对齐，切勿把地图占位文字当做实时画面。

GHUD 顶栏 OCR 不再允许连接窗口后直接使用未经确认的固定位置自动输入。打开 GHUD 识别 → 选择窗口/截图 → 预览画面 → 选择七个字段分别框选 **数字而非图标** → 保存确认 → 采样两次核验 → 检查字段置信度，最后决定是否自动推送。改变窗口、游戏 UI、画面偏移后必须重新确认。详细见 [彩排指南](postgame-ghud-overlay-fixes.md)。

### 赛后单字段 OCR：用鼠标框，不需要手填坐标（PR #70）
1. 「结算整页采集」上传本局截图后，在同一 Control 页展开「单字段 OCR」，选择「游戏评分」或其他字段；两个工具共享当前截图。
2. 点击「预览/刷新当前画面」，检查不是浏览器标题栏或黑屏。下拉选中玩家，在图上**直接拖出数字小框**；重复十名选手，或本队五行间距确定时用「按行距复制本队 5 个框」，并检查每个框。
3. 点击「识别当前选手」只采一个人，不用凑十人；或识别所有已框选行。检查原始 OCR、置信度、裁图，达到 85% 的可信字段方可批量应用；低分、纯黑或空白保留原值。需要时继续手工录入真实评分。
4. 这些框选坐标保存在当前浏览器，截图同会话复用，不跨设备自动同步。操作图与细节见 [赛后修复与 GHUD 彩排](postgame-ghud-overlay-fixes.md)。
