# 本地空间占用与安全清理

备份或排查上传耗时时，保留界面列为证据、比赛资料或用户上传的文件。#115 的临时目录验证覆盖写入后变化、引用保护和目录联接。[已测项目](../validation/storage-ocr-reliability.md)

Control → 窗口 → 设置 →「本地空间与安全清理」→「查看空间占用 / 仅预览」。首次只读扫描不会删除文件或启用定期清理。按大小查看目录、文件数、用途与可回收容量；扫描根目录显示在表格上方。

本机命令（在 `vite-project` 运行）：

```powershell
npm run storage:inspect
npm run storage:inspect -- --root ..
```

第一条查看应用子目录，第二条只读查看整个仓库（包含普通克隆的 `.git`）。Git worktree 的 `.git` 是指针文件，不展开外部共享 Git 存储。外置 DATA_FILE、模型和 OBS 录像不属于应用根目录，不能把该表当作整块硬盘占用。扫描超过 100,000 个条目或 5 秒预算会标为部分结果，已列大小只是下限。文件容量为逻辑大小，不是压缩/稀疏文件的实际磁盘分配量。

## 哪些文件可以删除

只有同时满足下列条件的文件才会进入清理预览：

- 来自本版 Playwright 截图调用或附件，生成完成后留下文件身份、大小、修改时间和 SHA-256 凭据。
- 位于 `artifacts/`、`test-results/`、`playwright-report/`，类型是相应测试截图、视频、跟踪包或报告资源。
- 生成时间及修改时间都超过保留期；内容、身份和大小仍与生成凭据一致。
- 未出现在当前比赛、历史状态或恢复 JSON 的引用中；没有同名 `.keep` 文件；不是硬链接、符号链接或目录联接中的文件。

旧截图不会仅凭文件名或目录名自动取得清理资格。首次安装时可回收为 0 是正常的，不能据此认定旧测试目录毫无垃圾。历史未知产物需要人工判断，本版不会批量补写“生成凭据”。

比赛历史、恢复备份、队标/选手照片、校准、密钥、OBS 录像、依赖、模型和未知目录不在删除范围。当前赛后 OCR 证据与选手图片共用上传存储，没有可靠的“临时裁图”来源标签，因此整个上传目录受保护；不以“暂未引用”为由删除。要保留已登记的失败样本，例如 `trace.zip`，在旁边建立 `trace.zip.keep`。

## 预览、执行与定期任务

先预览，再点击「立即清理已预览项目」。预览有效期 5 分钟，更改保留期后必须重新预览。执行前再次检查引用、内容、文件状态和路径；文件正在改写、被引用或被换成联接时跳过。只逐个删除文件，不递归删除目录。最近 20 次记录保留删除文件、数量、容量、跳过原因及延后原因。

定期清理默认关闭。先扫描载入当前配置，再设置保留天数（1–365，默认 14）和间隔小时（1–168，默认 24）。服务每分钟检查是否到期；重启后沿用已保存配置和最近执行时间。BP 已开始或本局未确认结束、OBS 录制中或已配置 OBS 的状态不可确认时延后；自动任务在未配置 OBS 时也延后。没有 OBS 配置时仍可在确认停止录制后手动清理。

单次删除最多 200 文件 / 256 MiB，并使用 5 秒循环工作预算；扫描和删除是不同阶段，文件系统单次 I/O 不保证硬实时。引用扫描超过数量/容量/时间上限、保护 JSON 损坏、维护锁冲突时停止清理。不要在清理过程中手工替换项目目录。删除不能由比赛 Undo 恢复。

## Windows 验收

1. 执行只读命令，确认根路径和大目录；先不要启用定期任务。
2. 在开发副本运行 `node --import tsx --test server/storageMaintenance.test.ts server/maintenanceBo7.test.ts`。测试仅删除自己创建的临时目录。
3. 对比过期测试图、同名 `.keep`、报告引用证据、修改中的文件；预览与实际删除数可以不同，跳过原因必须可见。
4. 联接回归会在预览后将白名单子目录替换为外部 junction，验证外部文件仍在。文件 symlink 创建需 Windows Developer Mode 或相应权限；权限不足会明确记录未测，不冒充通过。
5. 开始正常 BP / 盲选局、开始 OBS 录制、断开 OBS 后分别核对自动清理延后。不要在生产资料上制造过期或故障样本。
