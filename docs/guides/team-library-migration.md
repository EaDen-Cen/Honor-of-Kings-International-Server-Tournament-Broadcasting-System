# 队伍资料库：图片上传与跨电脑迁移（开发分支）

> 本指南对应 `fix/team-images-portable-library-20261025`。正式合并和实际运行前，请先通过自动测试与两台电脑实测；旧版客户端没有导入入口。

## 一、修复 JPEG 上传

- Control → 队伍设置 → 管理队伍资料 → 队伍资料编辑 → 选择图片。
- 首发头像、替补头像和队伍 Logo 均支持 PNG、JPEG（包括 `.jpg`/`.jpeg`）、WebP，单张最多 5 MiB。
- 原版本后端使用手写 JPEG 段头解析器；新版本改由 `sharp` 检查并完整解码图片；JPEG 自动校正 EXIF 方向并重新编码，检查像素上限（2500 万像素），不把扩展名当成图片有效性的唯一证据。
- 上传成功的队徽也保存在本机 `uploads/player-portraits` 目录，以便统一预览和迁移。文件保存为规范化的 `.jpg`、`.png` 或 `.webp`。
- 注意：PNG 和 WebP 验证通过后保留原始字节与透明度，以维持现有缓存和备份的兼容性。文件过大、类型不匹配或解码失败仍应拒绝。

## 二、快速导出

1. 在 **A 电脑**打开 Control → 队伍设置 → 管理队伍资料 → **跨电脑迁移队伍资料**。
2. 点击「导出完整资料包」，下载 `hok-team-library-YYYY-MM-DD.json`。
3. 文件包含队伍 ID、队伍名称、队徽、5 名首发 ID/分路/照片、最多 20 名替补的 ID/分路/照片、创建与更新日期。
4. 本机通过图片上传保存的图片，以及 `public/teamLogo`、`public/playerImg` 目录中已被队伍引用的图片，以 Base64 附带 SHA-256 校验值打包。
5. 访问口令、OBS 密码、AI API Key、比赛记录、识别缓存、导播布局 **不在此数据包内**。

**外部图片地址的限制：** `https://...` 及其他未托管图片 URL 在迁移后依然是原 URL，不能保证离线可用。建议迁移前用队徽或头像下的「选择图片」把要保留的外部图片保存成本机上传素材，再导出。导入预览会提示有多少未打包的图片 URL。

## 三、快速导入与冲突

1. 在 **B 电脑**进入同一界面，选择刚刚导出的 `.json` 文件。
2. 系统先验算数据结构、图片格式、单图片体积、总大小、校验码及队伍 ID，并展示队伍总数、图片数、新队伍数、同 ID 冲突数；此步骤不改动任何数据。
3. 选择冲突策略：**保留本机队伍（默认跳过）**，或 **使用导入资料更新同 ID 队伍**。
4. 点击「确认导入」，检查确认对话框。系统先生成本机恢复备份，再写入新图片并一次性合并队伍资料。
5. 导入后自动刷新队伍列表。当前比赛中的阵容不会被自动替换；如需换阵容，按普通流程载入保存的队伍。

**数据同步语义：** 合并是按稳定队伍 ID 做的单向复制，不是实时双向同步。重复导入「跳过」不会重复创建队伍；「更新」会更新同 ID 队伍。不同 ID 即使队伍名称相同也视为不同队伍。不会删除 B 电脑上独有的队伍。

## 四、安全与故障处理

- 端点均要求 Control 身份，生产环境继续校验来源。
- `GET /api/team-presets/transfer/export`：导出 `hok-team-library-v1` JSON。
- `POST /api/team-presets/transfer/preview`：请求体 `{ "bundle": { ... } }`，只读校验。
- `POST /api/team-presets/transfer/import`：请求体 `{ "bundle": { ... }, "conflict": "skip" | "replace" }`。
- 大小限制：单图 5 MiB，图片原始数据累计 96 MiB，请求体 135 MiB，图片最多 2000，队伍最多 300。
- 仅允许受限的本地上传图片路径或内置公开图片目录，导入会将打包图片重写至安全随机文件名；不从归档里的路径任意写盘、不自动向远程 URL 发请求。
- 如果引用的本地图片丢失，导出会提示缺少图片而不会生成不完整数据包；图片 SHA 不匹配或无法解码则拒绝导入。
- 修改现有队伍会先生成本机备份，导入过程中如果保存失败，新写入的图片会回滚，旧的队伍列表不会被覆盖。
- 此功能不代替完整比赛备份；需保存比赛进度请继续使用「恢复与备份」功能。
