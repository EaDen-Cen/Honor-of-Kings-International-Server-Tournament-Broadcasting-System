# GHUD：ADB 采集与中立资源累计数

本轮基于已合并 #111 的 main `8175270`，为待审查开发候选，未发布正式版本。真实短时采图不等于完整直播验收。

## 选择采集来源

Control → 窗口 → 局内 GHUD → 局内 HUD → GHUD 顶栏识别。

- Windows 窗口 / 静态截图：沿用 BP/赛后共享画面。截图只能审核，禁止自动发布。
- Android ADB：只供 GHUD 使用，不替换其他模块共享源。启动雷电，刷新实例，选择实例，点击「连接 / 重连并预览」。从运行中的雷电进程寻找相邻 adb.exe/ldconsole.exe；多安装目录时可在服务器本机设置 `HOK_ADB_PATH` 为已有 adb.exe 的绝对路径。

ADB 要求本机 Control，远程代理 Control 不可调用。实例通过 `ldconsole adb --index N --command get-serialno` 核验。不打开公网调试端口，不执行点击、安装、root、重启或任意 shell 命令。

## 校准与恢复

1. 分别在 Windows/ADB 内容选择中圈出 16:9 游戏区域；ADB 内容框独立。
2. 预览并检查七字段。经济框必须包含完整数字和 `k`：旧 70px 示例框会截断 10k 以上经济，本版默认扩至 90px。已有人工校准不覆盖，应重新检查。
3. 保存确认后手动采样两次，再开启自动采样/发布。切换来源、实例、尺寸或内容框会清除候选并要求重新确认。七字段框按来源/尺寸/内容框存于浏览器，最多 12 项；保存不等于自动批准。
4. 一次只处理一帧，不排队。失败保留可信比赛值、清除候选；检查设备后刷新实例或重连，重新取得两帧证据。目标一秒一次，但慢帧完成后再采下一帧，不保证 1Hz。

## 资源累计数与存活状态

两者独立。累计数支持 ±1、精确输入、冻结/恢复及来源/时间。人工修改或确认相同值都会冻结对应计数。新局清零并待核对；已提交局的历史 `liveGameStats` 快照保留当时累计数。

自动计数需单独框选**该类资源、该阵营实际可见的累计数字**，确认后解除对应冻结。资源选框仅对本次确认来源有效；换来源、刷新页面或资源名单改变后须重新核对。不得把总计同时框给暴君和主宰，也不能把存活字样、倒计时或击杀横幅作为次数。没有分类累计数字时保持人工输入。支持自定义资源名称，不猜测不同游戏版本的分类。

需两次独立 OCR、推进中的时钟、相同选框、≥85% 置信度、单调与增速检查；资源候选不走复用缓存。人工冻结、重启/Undo 前及跨局证据不会写入。中途启动可从实际可见的绝对累计数建立基线；没有累计数时保持「待核对」，不伪造完整事件统计。存活状态继续由人工设置。

## Overlay 与现场检查

顺序：蓝比分 / 蓝队 / 蓝资源 / 蓝推塔 / 蓝经济 / 蓝击杀 / 时间 / 红击杀 / 红经济 / 红推塔 / 红资源 / 红队 / 红比分。保留透明 1920×1080、默认 65% 宽、可调高度和完整模式第二行。

现场仍需检查实际浏览器窗口捕获/ADB 遮挡差异、10k/100k 完整经济文本、真实资源事件、断连恢复及长期 OBS 并发录制。[验证记录](../validation/ghud-adb-objectives.md)区分自动测试和真实验收。

命令依据：[Android 官方 ADB 文档](https://developer.android.com/tools/adb)、[LDPlayer 官方命令行说明](https://www.ldplayer.net/support/introduction-to-ldplayer-command-line-interface.html)。
