# 操作与可靠性改进说明

本次改进围绕同一条原则：比赛以服务器确认的状态为准，保留导播正在编辑的内容，拒绝迟到的识别结果覆盖新的操作。

## 导播设置

比赛和队伍设置现在会保留未保存草稿。其他页面修改了不同设置时，未编辑的字段会跟随更新；同一字段发生冲突时会提示重新载入并暂停保存，避免覆盖另一位导播的修改。关闭未保存的设置会提示确认。解说延迟输入跟随服务器实际值；空白、非整数或超出 0–3600 的值不能提交。

登录、访问设置和分享链接增加等待状态、重复提交保护及超时提示。缺少 `crypto.randomUUID` 的浏览器也能正常提交比赛操作、添加局内资源和队伍替补。密码保存结果不明确时，先用新密码确认访问，不要连续重复保存。分享网址只填写网站根地址；生成的解说与直播画面链接带对应的只读口令。

## 共享采集与人工纠正

各面板共用同一个游戏窗口。取消更换窗口会保留原来的采集；关闭某个面板不会停止其他面板正在使用的源。成功更换源后才释放旧源。新截图优先于仍未完成的窗口选择，迟到的窗口会自动释放。

更换来源、换局、离线、暂停或人工修改后，旧的识别请求会取消或被丢弃。人工调整最终英雄归属会暂停自动阵容同步；确认画面正确后再显式恢复自动同步。候选结果存在明显歧义时，需要人工核对。选手顺序以服务器实际确认的结果为准，确认成功后保留已核验的同步反馈。

局内数字、赛后数字及评分改为编辑完整数值后按 **Enter** 或离开输入框保存；**Esc** 放弃当前编辑。未保存输入不会被外部更新直接覆盖。局内未知经济或时间可以清空，清空也会冻结该字段的 OCR，避免马上被自动填回。需要自动读取时再恢复对应字段。GHUD 自动采样和自动播出会在操作确认期间暂停，确认后保留开启状态并重新核验两帧，避免每次成功写入后都需要重新开启。

经济时间线会跟随已保存数据更新，同时保留未保存草稿。遇到其他页面更新时可核对后保存，或选择恢复已保存内容。重复采集结算页会保留已经确认的身份映射，且只提交可更新的字段；受保护的人工值继续保留。

## 队伍与英雄资料

队伍库保存成功后直接更新列表，不会因随后读取列表失败而误报保存失败。关闭头像上传会释放等待状态，迟到的上传结果不会覆盖当前编辑器。切换队伍草稿前会保护尚未保存的修改。

英雄编辑器支持国服专有英雄及无原画英雄的资料编辑，保留切换英雄前的草稿，并支持中英文逗号分隔别名。保存状态以服务器确认结果为准。

## 存档和恢复

国服英雄、每队五个 Ban、20 个阶段以及经济/战绩页赛后数据均纳入恢复校验。恢复还会校验团队统计、经济时间线与字段边界。无效存档会明确失败并保留原文件，不会静默创建空比赛覆盖它。备份和导出增加超时、防重复及响应校验；失败后可以重试。

## 验证边界

自动验证包括构建、静态检查、服务端单元与集成测试，以及独立服务上的浏览器回归。浏览器测试使用可重复的画面、请求和异常场景验证业务行为；不代替真实 Windows 游戏窗口、显示缩放、OBS、隧道与远程解说的现场联调。国服自动识别训练和 Game HUD 的现有限制仍适用。

## 自动检查入口

在 `vite-project` 中运行 `npm run build`、`npm run lint`、`npm test`；首次浏览器验证前运行 `npx playwright install chromium`，随后 `npm run test:e2e`。浏览器回归会为每个用例启动独立的本地测试服务，数据和日志写入 `artifacts/e2e-*`，不使用正式比赛存档；若测试端口 3101 被占用会直接报错，不会停止已有服务。`CHROME_PATH` 可指定浏览器，未指定时优先使用 Windows 的已安装 Chrome，否则使用 Playwright 浏览器。

Windows 启停脚本的语法和进程归属逻辑可用 `pwsh -NoProfile -File scripts/managed-process.test.ps1` 验证；该检查模拟进程信息，不代表真实 Windows 启停联调。新增 GitHub Actions 会执行上述构建、静态检查、单元、启动器逻辑和全部浏览器回归，失败时保留日志与截图。
