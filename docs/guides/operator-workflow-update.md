# 导播操作台流程与连接可靠性改进

操作台顶部新增四步指引，依据服务器的比赛状态自动切换，不需要导播维护另一份进度：

1. **赛前准备**：核对队伍、首发、赛制与解说延迟。
2. **选禁操作**：显示当前队伍和选禁操作；可直接跳到选禁工作区。
3. **确认阵容**：核对 P1–P5 与最终英雄归属，再提交本局。
4. **记录与下一局**：提交后更新比分，再开始下一局；系列赛结束时提示处理赛后数据并备份。

“设置队伍”“检查赛制与显示”“选禁工作区”“比分与下一局”“赛后与备份”提供固定入口。窄屏下步骤以两列排列。提示跟随系统中英文设置，并向辅助技术报告等待确认与连接状态。

## 连接和操作确认

- 断线时保留最后收到的画面，但提示等待连接恢复；比赛操作继续受连接状态保护。
- 提交时采用最近收到的服务器修订号，避免 React 尚未刷新画面时使用旧版本。
- 一次仅等待一个操作确认。确认超时后重新连接、重新读取权威状态，不自动重放操作。恢复后先核对结果，再决定是否重试。
- 非法 JSON 消息会触发重连；会话切换会清理待确认操作与计时器。
- 访问设置打开期间，英雄选择快捷键暂停，避免输入设置时切换到英雄搜索。
- 延迟设置只接受 0–3600 的整数。
- 模拟器切换英雄池时立即刷新英雄列表；Ban 数量变化也会重新计算槽位映射。

## 验证范围

新增浏览器回归测试覆盖手机导航、完整选禁/提交/下一局流程、中英文提示、异常消息重连，以及未确认操作超时且不重复提交。另运行生产构建、静态检查及既有服务端和浏览器回归测试。

这些检查不能替代真实赛事机上的 Windows 原生采集、游戏窗口识别、OBS 和远程解说联调。Game HUD 保持项目现有 Experimental 定位；上线赛事前仍应按现有发布验收流程进行现场演练。
