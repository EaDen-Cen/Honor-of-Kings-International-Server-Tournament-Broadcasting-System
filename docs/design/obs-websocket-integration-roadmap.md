# HOK Broadcast × OBS Studio 双向控制与单人导播自动化路线图

> 状态：**设计企划 / 尚未实现**；创建：2026-10-19；对应里程碑：M24（优先级调整为 P0）  
> 依据：[2026-10-18 双场实战复盘](../validation/live-two-match-retrospective-2026-10-18.md)  
> 前置缺陷：**最终阵容英雄归属检测到变化但不一定应用成功（P0）**。此问题必须在自动联动正式启用前修复及复测。  
> 基本原则：少操作、可人工接管、状态可信、失败可见、不破坏 BP、录制及 MVP 已稳定的主链路。

## 1. 需求背景

现有系统通过 OBS Browser Source **单向**渲染 Draft、MVP、赛后对位及实验性 GHUD；Control 还不能主动切换 OBS Program Scene、控制 BGM 或读回录制状态。两场实战暴露了导播必须同时顾及 BP、P1–P5 身份、转场、游戏/解说音频、录制磁盘和赛后数据的负担。第二场 E 盘容量耗尽导致录制中断。

目标是建立本地优先的 **双向 OBS 控制器**：HOK Broadcast 下发经过授权的场景/音频动作，OBS 回传真实的当前场景、录制/直播和音频状态；用一次按键完成一个阶段内的安全联动。

**非目标**：重写 OBS 编码/渲染器、直接实现游戏 API 识别、自动决定 MVP、未经验证自动转场、将 OBS WebSocket 开放至公网，或把 OBS 本地配置混进可以分享的赛事存档。

## 2. 当前架构与计划架构

### 现状（已实现）

```text
游戏 / BP 采集 → Node MatchState → HOK Overlay URL → OBS Browser Source
                Control / Caster
```

### 计划（尚未实现）

```text
导播 Control（React）
    │ 授权命令 + 状态展示
    ▼
HOK Node Server
    ├── ObsAdapter (obs-websocket-js)
    │      ├─ 场景控制 / Scene status
    │      ├─ 音频输入 / BGM fade
    │      └─ 录制/直播状态回传
    ├── Preset Engine（Waiting/BP/Game/Pause/Postgame/Matchup/MVP/Safe）
    ├── Command Gate（权限、去重、超时、手动覆盖、安全失败）
    └── Record Health（本地输出目录与磁盘剩余容量）
            │
      obs-websocket 协议 5.x
      ws://127.0.0.1:4455（默认示例，可配置）
            ▼
OBS Studio（本机）
    ├─ Scenes / Browser Sources
    ├─ Audio Inputs / Media Sources
    ├─ Recording / Streaming
    └─ OBS Event → Node → Control
```

- OBS Studio 28+ 的内置 obs-websocket 提供 5.x 控制接口；使用 `obs-websocket-js`，部署前核对当前 OBS 及库版本的兼容性。
- 不在浏览器中保存或使用 OBS 密码直连 OBS；由本地 Node 负责连接、最小权限 API 与返回状态。
- OBS 的**实际 Program Scene 和 Recording 状态**是播出控制的权威来源。现有 MatchState 继续负责比分、BP、阵容和赛事数据；不能让两套状态互相循环覆写。
- OBS 连接或控制失败不能阻断 BP 屏幕采集、Player ID OCR、Overlay 显示、Caster 或本地赛事数据持久化。

### 计划文件职责（只是拟建文件）

| 模块 | 主要职责 |
| --- | --- |
| `server/obs/ObsAdapter.ts` | 握手认证、状态查询、事件订阅、重连与版本兼容 |
| `server/obs/ObsCommandQueue.ts` | 有限动作白名单、权限验证、命令去重、超时及错误提示 |
| `server/obs/ObsPresets.ts` | 阶段 → OBS 场景、音量与转场动作的可配置映射 |
| `server/obs/ObsRecordHealth.ts` | 录制输出路径、目标卷剩余空间、预计录制时间与告警 |
| `src/control/ObsDirectorPanel.tsx` | OBS 连接/场景/BGM/录制状态、告警及导演预设按钮 |
| `src/shared/obsProtocol.ts` | 授权命令/事件类型，和赛事 Draft Action 分离 |
| `docs/guides/obs-director-setup.md` | 集成真正实现后编写的安装、配置和现场故障操作手册 |

实际开发应复用仓库现有访问控制、Node 服务路由、状态订阅、日志和设置框架，而不是另建未经审计的公共接口。

## 3. 单人导播阶段预设

| 阶段 | 场景动作 | 音频动作 | 触发方式 |
| --- | --- | --- | --- |
| Waiting / 赛前 | Waiting 场景 | 等待音乐渐入；游戏降低 | 导播按钮 |
| BP / 选禁 | Draft 场景与 Browser Source | BP 曲目/解说音量预设 | 导播按钮 |
| Game / 正赛 | Game 场景 | BGM 渐出；游戏音量恢复 | 导播按钮；未来可建议 |
| Pause / 暂停 | Pause 场景 | 游戏降低；可播放提示音 | 导播按钮 |
| Postgame / 结算 | Postgame 场景 | 结算音乐渐入 | 导播按钮 |
| Matchup / 对位 | 对应五个固定角色 OBS 场景 | 维持结算音频预设 | 导播选择分路 |
| MVP | MVP 场景 | 颁奖音乐渐入；游戏降低 | 导播按钮 |
| Safe / 紧急 | 可配置安全静态画面 | 一键静音 BGM/SFX；不停止录制 | 紧急按钮 |

所有场景名、音频输入名和媒体源均由用户与 OBS 已有资源绑定，不得硬编码。M24 首期坚持**人工一键触发**，不是将每次 OCR/英雄锁定直接转换为转场。

**示例：“进入比赛”**：检查 OBS 已连接与目标场景可用 → 对 BGM 执行淡出 → 切换 OBS Program Scene → 按用户预设恢复游戏/解说音量 → 等待 OBS 回执/事件确认 → 展示真实结果。任何部分失败应明确标记并允许人工重试或回到安全场景。

### 控制台交互

- 显示 OBS 连接状态、正在播出的场景、录制/直播状态、录制时长、BGM 音量及上次操作结果。
- 阶段按钮保持简洁，适合单人导播；高级场景绑定、音频源映射、自动化开关收在设置界面。
- 当导播在 OBS 中手动切场景时，Control 同步真实状态并**撤销冲突的自动动作**。
- 提供 BGM 一键静音、渐变时长（如 0–3 秒）、Safe Scene、取消正在进行的渐变。
- 不要把“命令已发送”显示为“OBS 执行成功”，须等待 ACK 或实际状态确认。

## 4. 音频方案

建议在 OBS 内映射四种逻辑输入：`Game`、`Caster`、`BGM`、`SFX`。可沿用现有 Voicemeeter Banana 的设备路由，但 HOK 只操作经配置的 OBS 输入源。

1. **阶段音量预设**：按场景设置目标音量和静音状态，实际声卡设备由 OBS/Voicemeeter 负责。
2. **渐变**：以合理间隔平滑调整音量，避免密集 WebSocket 消息；重复动作取消旧渐变，并从 OBS 当前真实音量继续。
3. **解说 Ducking（后续）**：优先结合 OBS 可用的 Compressor/Sidechain 或当前音频路由；WebSocket 本身不等于语音活动识别。
4. **BGM 控制**：首期操作现有 OBS Media Source 的播放和输入增益；不要求新增独立播放器，更不能在重连时重复开歌。
5. **应急回退**：独立 BGM/SFX 静音，不得误静音解说和游戏；不以停止 OBS 录制处理声音故障。

## 5. 录制状态、E 盘空间与中断预警（P0）

这一项来自真实故障，必须与首期 OBS 集成并行实施：

- 从 OBS 读取**真正的**录制/暂停/停止状态，识别录制意外中止与错误；广播给授权导播界面。
- 读取 OBS 实际输出目录（如果当前 OBS API 不提供足够路径信息，则要求导播明确配置并标记“手动指定”）；不可把 E 盘写死。
- 由运行于**录制电脑本地**的 Node 服务查询目标盘剩余空间。普通浏览器和云端 Node 无权直接读取导播电脑任意盘符。
- 显示剩余空间、预期还可录制时间估计与置信程度；可设置绝对容量或“预计不足覆盖余下比赛”的警告阈值。VBR/可变素材速率需标注估算偏差。
- 在开录、每局开始和比赛期间按合理周期检查；已停止录制、空间不足、路径失效时明显提醒。
- **默认只警告、不自动删除素材、不自动停止录制、不在文件写入中强制切换目录**；现场必须有备用录制方案。

## 6. 最终阵容归属可靠性：M12/M12A 前置 P0

**2026-10-19 新增真实现场问题**：程序已经检测到英雄交换/最终归属变化，但在实际比赛中没有把变动应用到权威最终阵容。这会影响选手 ID 对应英雄、赛后角色对比及历史数据。

### 代码检查（现状，非根因结论）

当前 `src/control/LineupAssignments.tsx` 使用 `solveLineupTeam` 解析两队各 5 个槽位。检测变化后，只有在全部条件满足时才会尝试写入：

- 五个英雄的映射能得到唯一可信解；原有 `bluePicks / redPicks` 是受限候选集。
- 蓝红双方最低相似度均 ≥0.50、平均相似度均 ≥0.65。
- 自动模式要求同一候选阵容连续稳定出现两次；显式 `scan(true)` 可以跳过连续两次条件，但**仍要通过相似度门槛**。
- `draftComplete` 为真、当前局未 `committedGameId`、未被 `disabled` 才调用 `set_lineup_assignments`。
- 现有提示中“已发送自动同步”表示调用 `send()`，**不是服务器已接受并持久化的 ACK**；服务器还会执行 `validateLineup`。

**因此，现场症状可能来自阈值/稳定性门槛、双队约束、请求取消/比赛状态变化、服务器校验失败或反馈缺失；尚未通过日志确定实际根因。不能直接降低阈值来冒险覆盖阵容。**

### 必须完成的修复

1. 显示清楚的状态机：`Detected → Needs Review / Stable → Submitting → Applied (server-confirmed) / Rejected`，同时暴露未应用原因。
2. 把“识别候选”“导播手动确认”“最终阵容权威保存成功”分离；人工确认应能接管已有可信候选，不受后台扫描按钮忙碌状态不必要阻挡。
3. 自动提交后通过版本号 / 比赛局号 / 队伍 ID / 返回 MatchState 核对蓝红两队 `assignments` 已改变。超时、服务器拒绝或状态冲突时保留候选、明确提示，不假装成功。
4. BP 选角历史保持不变，最终持有者独立存储；支持**帮抢、代选、英雄互换**、多次交换、先手/换边、十人位置/ID 核验，并保持英雄不能无故新增/重复。
5. 若服务器已提交本局或切换游戏，拒绝迟到 OCR 写入；为待处理扫描/写入提供取消、重试和人工恢复。
6. OBS 自动场景建议只能依赖**服务器已确认的最终阵容及玩家身份**，绝不能因为前端“检测到了变化”就切换转播/生成看似正确的赛后对位。
7. 新增 Mock server、浏览器 E2E 与真机测试：高置信度自动成功；候选可见但阈值不足；一队可信一队不可信；自动关闭；manual Apply；服务器拒绝；请求重连；BP 帮抢→赛后交换；P1–P5 错序；重复连续两帧；切局并发；OBS/CPU 高负载。

**验收门槛**：当 UI 显示“已应用”时，必须从服务器读取到相同的最终阵容；应用失败在导播界面可见且有安全人工兜底。最终阵容与实际游戏一致，十名选手归属及五个对位图无错配。**完成该门槛之前禁止依赖它自动切换 Game 阶段。**

## 7. 部署、安全与权限

- OBS WebSocket 只绑定回环地址或受控内网，开启密码。**不开放 4455 公网端口**；OBS 密码仅本地受保护保存，不写 Git、日志、可分享备份或远程浏览器。
- Control 角色有权发送受限 OBS 命令；Caster/Overlay 不得调控制接口；对输入地址、场景、音源建立允许列表，避免 SSRF 与任意本地服务操纵。
- 独立命令 ID 去重、单次动作超时、断线后先读取 OBS 实际状态再重试。手动修改永远优先。
- 如果 HOK 后端迁移到云端，新增本地 `OBS Agent` **主动出站连接**；使用设备配对、可撤销凭据和限制命令。云端的 `localhost` 不是导播 PC。
- 正常断开 Control/Agent 不能关闭 OBS、结束录制或停播。停止录制/推流如未来提供，应作为高风险独立动作要求额外确认。

## 8. 开发阶段（按实战收益排序）

| 阶段 | 优先级 | 交付成果 | 最低验收 |
| --- | --- | --- | --- |
| **前置 M12A 修复** | **P0 阻断项** | 解决最终阵容检测但未应用；服务端 ACK、错误提示、帮抢/交换测试 | UI 说“已应用”时后端阵容一致；十人归属正确 |
| **M24.0 连接与遥测** | P0 | OBS WebSocket 配置、认证、重连、当前场景与录制状态 | 断开/重连不会影响 BP，OBS 状态准确 |
| **M24.1 一键手动场景** | P0 | Waiting/BP/Game/Pause/Postgame/Matchup/MVP/Safe 映射与动作反馈 | 能切指定场景，OBS 手动操作优先 |
| **M24.2 音频动作** | P0 | Game/Caster/BGM/SFX、淡入淡出、一键 BGM 静音及阶段预设 | BP→Game→Postgame→MVP 不需多次拖动推子 |
| **M24.3 录制安全** | P0 | 录制中断提醒、真实输出目标盘预检、可用空间警告 | 实机模拟容量不足/录制意外停止能发现 |
| **M24.4 阶段建议** | P1 | `Off / Suggest / Trusted Auto`、人工覆盖和恢复自动 | 未核验 BP/最终阵容不会触发自动切镜 |
| **M24.5 高级音频与远程** | P2 | Ducking、媒体源管理、云端受控 OBS Agent | 不泄露 OBS 密码和公网端口；设备失联安全 |

首版不追求“全自动”，优先保证导演按钮响应、OBS 状态真实、音乐动作平滑、录制不漏检。最终阵容可靠性是视频自动切场景与赛后统计的共同前置条件。

## 9. 测试与验收清单

### Mock / 单元测试

- [ ] OBS 未开启、密码错误、协议不兼容、场景不存在、音频源丢失、命令超时、服务器重启和重连。
- [ ] 重复按键、HTTP 重试不会重复播放音乐/反复切场景；旧命令不能覆盖手动操作。
- [ ] OBS 密码不回显、不进比赛备份/日志；非导播无权控制场景或读取本地路径。
- [ ] 一次预设内某一步失败时显示具体失败动作，安全状态不强制停播。
- [ ] 最终阵容候选值、提交 ACK、服务端拒绝、英雄交换/帮抢流程的竞态测试。

### OBS 实机（必须与 CI 区分）

- [ ] Windows 本地 OBS Studio + HOK Node + BP OCR + Discord/解说同时运行；测 CPU、内存、OBS 渲染/编码掉帧、声音同步。
- [ ] 1920×1080 验证 Draft、Game、五个独立对位、MVP、GHUD（仍 Experimental）场景的实际可读性。
- [ ] BP→Game→Postgame→MVP 由单人完成，记录每阶段手动操作次数、耗时和补救次数。
- [ ] 测 BGM 0/1.5/3 秒渐变、游戏音量与解说优先、BGM 静音/恢复及重连不重复播歌。
- [ ] OBS 录制目标输出盘的容量不足、录制意外终止、路径切换、权限异常和 VBR 误差警告。
- [ ] 真实帮抢/换英雄与 P1–P5 顺序后最终归属一致；失败提示明确，不误播跨角色对位。
- [ ] 手动 OBS 切换后，Control 能正确刷新并避免抢回错误场景。
- [ ] 断开 HOK 控制不终止 OBS 现有直播/录制；关闭 OBS 也不使 Control 失效。

## 10. 发布条件

所有功能状态必须区分 `Planned` / `Implemented` / `CI-validated` / `Real-OBS-validated`。本文目前全部 OBS 控制能力均为 **Planned**；Browser Source 单向展示属既有功能。

发布前同步更新根 README、`MILESTONES.md`、`docs/README.md`、`docs/design/architecture.md`、接口指南、操作指南与测试记录。严禁将规划描述成已经上线的 OBS 控制能力。GHUD 仍为 Experimental，不应作为唯一官方比分来源。
