# HOK Broadcast V2.2

## 操作变化

比赛设置中的 BP 形式、BP 规则、BP 先手方、换边方式相互独立。保存设置后全端同步；比分仍点击即同步。

- **底部横排**：顶端比分栏，底部横排十张英雄卡，历史和禁用位在卡片上方，中间透明。
- **左右竖排**：同一顶端比分栏，左右各五张卡，历史在底部中央，禁用位在底部两侧。
- **交换队伍显示位置**：队伍在左右之间交换，比分及选手一起跟随。
- **队伍位置不变，仅交换蓝红方**：原队伍仍留在原画面位置，只改变蓝红归属及配色。历史限制仍按队伍 ID / 选手 ID 判断。
- **BP 先手方**：蓝方、红方可独立选择。首次禁用后锁定；重置当前 BP 或开始下一局后可修改。换边不会自动改变先手方。

换边仅能在本局 BP 开始前执行。已完成的比赛仍按“确认本局有效 → 更新比分 → 开始下一局”操作，提交不会清空当前画面。

## 选手形象

每位选手有独立的形象地址与预览，支持 HTTPS 链接或本地路径，最多 1000 字符。照片、选手 ID、分路和英雄归属按同一位置对应。

本地图片放在 `vite-project/public/playerImg/`，例如 `player1.png`，在设置中填 `/playerImg/player1.png`。添加或替换本地图片后执行 `npm run build`，再刷新浏览器源。没有上传功能；测试截图中的英雄图仅作为测试用图片，不会写入正式选手配置。

未选英雄：选手形象 → 队徽 → 编号占位。图片加载失败也会降级。

底部布局选英雄时先用白色覆盖，再在白层后切换英雄图，然后白层向上移走、文字淡入。左右布局按实际画面位置向内滑入，与蓝红身份无关。比分、语言和无关快照不会重播；撤销后重选会重播。启用系统减少动态效果时直接更新图片。

## 兼容与部署

沿用当前状态、认证、WebSocket、延迟队列及持久化。旧存档、撤销记录、延迟快照及历史中的队伍会自动补齐新字段，无需删除 `data/match.json`。

默认：蓝先手、蓝方在左、交换队伍显示位置、五个空形象地址。历史记录新增 `firstPickSide`，保存该局先手。

一键启停和 Cloudflare 脚本保持原样。源码修改后先构建，再重启服务，使前后端同时升级；旧进程不能直接支持新增控制项。

## 验收范围

服务端测试覆盖两种 BP 形式的红先手完整流程、先手锁定/撤销/延迟、两种换边和比分归属、Global/Player 历史跟随、地址验证，以及各类旧快照迁移。

浏览器测试覆盖 1920×1080 顶栏居中、底部/左右真实布局、照片降级、颜色归属、动画顺序/方向和不重复播放、移动端设置、减少动画和延迟解说。另保留现有 Normal/Player/Global、断线恢复和完整语言切换测试。

测试使用隔离端口 3101 和临时比赛存档，不修改正式比赛。浏览器截图存于 `vite-project/artifacts/v22-*.png`。实际 OBS Browser Source 及真实游戏画面叠加效果，仍需在导播环境做最终彩排。

## 对局期间临时调整（2026-09-19）

比赛设置内的选手 ID、形象地址和分路在 BP/比赛期间仍可修改，保存后导播和 Overlay 实时更新，解说按原延迟更新。选禁结果及进度保留，可撤销。已提交历史保持原始快照，不被后续名单修改覆盖。选手 BP 模式仍检查 ID 唯一性及已有英雄的个人历史资格；如果换入的选手此前已用过当前英雄，保存会被拒绝且原状态保留。BP 先手和比赛规则仍按原时机锁定。

## 全局 BP 防浪费 Ban 位

仅全局 BP 生效：当前 Ban 方不能禁用对手在本系列赛此前已提交有效局中选过的英雄。控制台置灰并说明原因，服务器也会拒绝，且不消耗 Ban 位或推进阶段。判断跟随队伍 ID，换边后继续生效。己方历史不触发这项限制；普通 BP、选手 BP 不应用此规则。当前局已选或已禁英雄仍受原有重复检查限制。
