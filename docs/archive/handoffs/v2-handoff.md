# HOK Broadcast System V2

## 本轮实现

- 保留原 React / Node / WebSocket 架构及三个入口，服务端继续决定所有比赛状态。
- `draftMode` 仍表示本局形式：`match` 每队 4 禁，`normal` 每队 2 禁。
- 新增 `draftRuleMode`：`normal` 普通 BP、`player` 选手 BP、`global` 全局 BP。
- 共用 `draftHistory`，只保存经导播确认的有效局。当前禁用始终保存在原 bans 数组。
- 每队新增稳定 `id`；换边交换队伍、名单、分路与比分，历史按队伍身份归属，不按当时颜色归属。
- 选手 BP 按实际 Player ID 比较（去除首尾空格、统一大小写及 Unicode 表示），而非仅按位置序号。换位置、替补和换边后仍正确追踪。
- 即时比分操作；其他设置保留保存按钮。加减比分不会提交未保存队名，也不会丢失正在编辑的设置。
- 新版 OBS 图形：中央比分、当前规则、有效局历史、当前禁用、十张英雄卡、选手 ID、浅色分路图标条。
- 界面和英雄名使用服务端语言；队名、Player ID 保留原文。解说继续只读取延迟快照。

## 比赛当天操作

1. 在“比赛设置”选择 **BP 形式** 和 **BP 规则**。本赛事选择全局 BP；其他赛事可独立选择普通或选手 BP。默认 4 禁保持不变。
2. 填写两队名单及分路。选手 BP 需要十个非空且唯一的 Player ID；替补填写本人自己的 ID，不能沿用被替换选手的 ID。
3. 根据轮次点选英雄；选人提示明确当前对应的选手位置。历史不占用当前 Ban 位。V2.2 后，全局 BP 还会禁止 Ban 对手此前有效局已选过的英雄，避免浪费禁用机会；普通/选手 BP 不应用这条限制。
4. 选禁完成后，使用“英雄归属校对”核对五个位置；下拉选择另一英雄会交换归属，服务端再次检查选手资格。
5. 比赛实际结束且裁判认定有效后，点击 **确认本局有效**。此操作保存历史并保留画面，不自动加分、不立即清空选禁。
6. 使用比分 `+ / −` 更新结果，点击 **开始下一局** 并确认。只允许进入比分对应的紧接下一局；系列赛达到胜场上限后不能继续开局。
7. 若需要换边，在下一局选禁开始前点击 **交换蓝红方**，再调整替补名单。

### 重赛、重置和撤销

- 未提交的无效 BP：重置选禁，再重新录入；不会进入有效历史。
- 沿用同一 BP 重开：保留当前画面，无需重复录入或重复提交。
- 已提交：防止相同局号重复提交。提交错误时，逐步撤销比分/开局等后续操作，直到提交前，再重新确认或重置；撤销本身也有解说延迟。
- 重置选禁：保留此前有效局历史；已提交的当前画面需使用“开始下一局”，避免误清。
- 重置整场：清空比分、当前选禁、有效历史及进程，可通过原有 Undo 恢复。
- 规则在首个选禁操作后锁定；首局无历史时可重置选禁再修改。已有有效历史后，必须重置整场才能更改规则；系列赛赛制此时也锁定。
- 选手及分路在本局选禁期间锁定，下一局选禁前可修改。队名和队徽修改不改变稳定队伍身份。

### 局数和比分

`gameNumber = min(blueScore + redScore + 1, BO 最大局数)`，每次比分更新立即计算。
本局开始时另记录 `draftGameNumber`，历史和当前选禁画面使用这个固定局号，避免赛后加分将 Game 1 的英雄误标成 Game 2。
设置面板显示比分推算的局号；开始下一局后，新的选禁画面使用该局号。

## OBS 接入与验收

Browser Source 使用 `/overlay/draft#token=你的Overlay口令`，尺寸 **1920 × 1080**。
“赛事卡片”为完整高度，“紧凑卡片”为较矮版本；两者都使用新版卡片架构。
分路图标来自本项目 SVG，根据 `playerRoles[index]` 显示，不依据英雄职业推断。
当前素材仍使用已有英雄头像；本轮未重新核对或扩充英雄数据库。

已完成 Chromium 中的画布边界、透明背景、中央比分、三局历史、换边、角色图标、语言和实时同步检查。
截图位于 `vite-project/artifacts/v2-{normal,player,global}-overlay.png`。

**尚未完成 OBS 实机验收**：尝试隔离的便携测试实例未能启动，因此不能声称已验证 OBS 内置浏览器渲染或实际节目采集。隔离副本清理命令也被自动审批拒绝，副本暂留 `vite-project/artifacts/obs-portable/`，可手动删除。
实际彩排应在 OBS 确认：画面透明、长队名不遮挡比分、十张卡片和历史完整、刷新来源后恢复，以及解说画面和音频的真实同步。

隔离方式参考 [OBS 便携模式](https://obsproject.com/kb/portable-mode) 和 [启动参数](https://obsproject.com/kb/launch-parameters)。这些是验收工具参考，本轮没有加入产品级 OBS 自动切场功能。

## 启动 V2

在原服务终端按 `Ctrl+C` 停止旧服务，然后在 `vite-project` 运行：

```powershell
npm run build
npm run server
```

打开 `http://127.0.0.1:3001/control` 并刷新。若提示旧服务，说明 3001 上仍运行原来的进程。
本次会话无法停止该旧进程（Windows Access denied），需要原启动终端或拥有该进程权限的用户操作。
